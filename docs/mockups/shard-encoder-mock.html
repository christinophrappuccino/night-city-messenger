SHARD ENCODER — player-facing data-shard authoring

The player-side replacement for the one-page ShardConversionFlow wizard. Four stages, each with its own skill and its own GM knobs, ending in the same three-rung ladder the upload console already uses. Program (payload / malware) authoring is a branch of stage ②, gated by rank and resolved by a craft-skill choice whose margin sets how good the program is, not just whether it exists.

Today (ShardConversionFlow)

  • One roll on ONE skill (Interface) caps everything: encryption DV, ICE type, key item and which content types you may write.
  • Six of the eighteen types, on the old flat forms — none of the WYSIWYG editors, templates or examples.
  • Pass/fail with a ceiling; a player-made dossier carries no quality, so nothing can ever reveal it as a fake.
  • GM controls: a floor, a skill name, a Black-ICE toggle. No allow-list, no cost, no audit.
  • Payloads are a flat form with no relation to the Workshop's ability catalog; players can't author malware at all.

Encoder

  • Container vs content are different questions — a netrunner locks a shard well, a forger fakes a document well. Two skills, two stages.
  • All 18 types, reusing the editors that already exist; the GM curates which ones players see.
  • The upload ladder (clean / sloppy / rejected) replaces pass/fail, so player-made content has a quality and a tell — the blackmail forgery can be caught.
  • Programs come from the Program branch: rank unlocks abilities (scanner at 0, keylog at 4, backdoor at 7), the player picks the craft skill, and the roll margin sets charges, stealth DV and run DV. Same programToEntry shape the Workshop writes, so the Program Deck and upload just work.
  • GM: one Player Authoring card, a PLAYER-MADE badge on the Shards list, and a botch consequence.

Why a separate Blank stage

Today the item picker, the name and the roll sit on one screen, so a player can't tell which part of the shard the roll is about. Splitting the physical thing off makes the later stages honest: the roll is about the content, the lock is about the container.

Buy a blank is the on-ramp the current wizard lacks: right now a player with no convertible item simply can't make a shard. The price is a GM knob and defaults low; it also gives the botch consequence something to burn.

The Operator card is the same live-read pattern as the dossier combat profile — the skills shown are the ones the later stages will use, so the player knows before they start which stage they're good at.

Why the skill lives on the tile

The tile is the whole pitch of the stage: what you can make, with which skill, at what odds — before you pick. A player whose Forgery is 1 sees at a glance that a fake dossier is a coin-flip and a spreadsheet isn't.

The skill table is data, not code: a default map ships (Forgery for documents / records / dossiers / credentials / chat logs, Library Search for research, Accounting for banking and spreadsheets, Perception for galleries and AV, Interface for programs), and the GM overrides any row in the Admin card. Alt skills with a penalty let non-specialists try.

Locked tiles stay visible. "GM disabled" and "Interface 4+" are different messages, and both teach the table what to change — the same rule as the terminal's dead exfil chips.

Payload and Malware tiles don't open an editor. They route to the Program branch (next view), because a program isn't written, it's built.

Why the skill CHOICE, and what it buys

The current wizard rolls Interface and caps a DV. That answers "may I?", not "how good is it?". A program has real numbers a roll should own: charges, stealth DV (what ANALYZE / SYSTEM SWEEP must beat), and run DV (what the operator rolls later to execute it). The Encoder makes the margin set all three.

Rank gates, roll grades. Rank in the craft skill decides which abilities exist for you at all (scanner at 0, keylog at 4, backdoor / deployICE / logic bomb at 7 — the GM's thresholds) and adds base charges. The roll decides how well the one you picked came out.

Choosing the skill is a real trade. Interface is the netrunner's tool: no penalty. Electronics/Security Tech builds the same thing at +3 DV — a tech can jury-rig a keylogger. Cryptography at +5 only makes sense for keylog / backdoor. The chips show every option with its odds, so a non-netrunner sees exactly what the penalty costs before rolling. GM can remove or re-price any alt.

Nothing new downstream. The result is the same programToEntry shape the Workshop writes (uploadable, uploadEffect, charges, stealthDV), so the Program Deck shows it, the upload go-bag carries it, and SYSTEM SWEEP catches a sloppy one. The upload roll stays a separate intrusion roll — craft quality is decided here, once.

Why the console, why the ladder

This is the existing runSecurityConsole with the verdictFor hook the upload flow added — three rungs, an amber is-warn tone for sloppy. No new modal. It inherits the viewer's preset, docks under Tier C, posts the same chat card.

The ladder is stated before the player commits, every time, because the thing that went wrong on the first upload play-test was that nobody knew a bad miss was still "success". Here a bad miss is rejected, and the GM decides whether that burns the blank.

Switch the result with ?result=clean|sloppy|rejected|await. await is Tier C: the GM adjudicates and the console docks, exactly like a siphon.

For non-program content the same console runs with the content skill (Forgery for the payroll document) and the same three rungs; sloppy stamps a low forgeQuality so ANALYZE flags it FORGED when it's later handed over or planted.

Why one card

Everything the Encoder reads is a world setting shown here — nothing is hard-coded in the wizard the way the tier thresholds are today. The shipped table is the default; a GM who wants "no player malware, ever" unticks one select.

Decisions locked 2026-09-12: blank price 50 eb (a knob) · all 18 types available, 11 on by default · pricing Propose (player names it, the GM approves / counters / denies, only then does it land on the item) · a rejected encode does what the blank\'s tier says — Scrap and Standard brick, Premium survives wiped (+1 craft roll perk); a natural 1 is one step harsher · tiers are GM-defined with an item picker (the burn-picker pattern), anything unlisted is Scrap · re-encoding a sloppy shard and copying a clean one are allowed at a DV penalty · gear modifiers, time cost, assist and signature effects are optional toggles, off by default.

Audit is not optional. Player-made forgeries need the same "what's been planted where" trail the upload arc required, so an encode writes a Security-tab row with the quality, and the shard carries a PLAYER-MADE badge in Admin → Shards. This is how the GM knows the blackmail dossier is fake before the NPC does.

It follows the admin-panel vocabulary: display font chrome, mono for values, 2px radius, the .ncm-ct-row__check checkbox — the reference implementations from the Security-tab cohesion pass.
