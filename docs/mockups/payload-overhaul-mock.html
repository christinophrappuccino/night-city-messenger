PAYLOAD OVERHAUL — 3 VISUAL DIRECTIONS (pick one, or a hybrid)

Scope already locked: PAYLOAD = utility programs (the operator's tools — malware stays the hostile sibling). Executing runs through the SecurityConsole (optional GM gate, fail can trace), then applies the configured effect: module-native (icebreaker / skeleton key / scanner / jammer) · linked Macro · GM adjudication alert — with optional duration (active → auto-expires on the game clock). Disguise gets implemented (bottom of page). The three directions below only differ in how the file renders and what the execute moment looks like — behavior is identical.

DIRECTION A — "LIVE RUN" · the card executes into a console

Idle file card → RUN expands a phosphor console inside the card; authored output lines (a new composer list — write your program's stdout) type out with a progress sweep, verdict pops, then an ACTIVE strip with the effect countdown. The execution is the theater. Best fit with the WYSIWYG pass: the composer's output editor would be the same live console.

DIRECTION B — "INSTALLER / MANIFEST" · corp software package

A signed software manifest: metadata grid (version / size / signature / license), a requirements list that reads the real world state (uplink up? account admin? — unmet = can't run), staged install bar (UNPACK → INJECT → CLEANUP) through the SecurityConsole, then an ACTIVE ribbon. Feels official and corp; requirements double as GM-authorable prerequisites.

DIRECTION C — "PROCESS DECK" · a daemon you keep running

The payload renders like a process in a task manager: status LED, fake PID/CPU/MEM meters (flavor), the effect readout, and — the star — a live uptime + expiry bar for timed effects. RUN spins it up; the GM (or a killswitch roll) can KILL it early. Strongest fit if timed/daemon effects are the heart of the type; idle state is the least flashy of the three.

SHARED — DISGUISE (all directions)

A disguised payload renders as its cover type (here: a NOTE) for players — occasionally glitching for a split second (the only visual tell, optional). GM always sees the red tag. A player can SNIFF a suspected file (roll vs sniffDV via the SecurityConsole) to unmask it; executing it obviously also reveals it.
