## Architecture: Conversations (2.1, built 2026-11-02, not live-tested)

Group chat beside mail. **`dev/design/CONVERSATIONS.md`, "Revision" and "Gap tracker", win over the older text there.** Deliberately loosely connected: no Desk, Overview, trace, sniffer, terminal mirror or Last Interaction; shard and terminal chat logs are unrelated. World setting `conversationsEnabled` (default off until release; off = no hooks and no UI). Sims `test-conversations.mjs` (rules + real service), `test-conversation-screens.mjs` (every button has a case, every class is styled, every called method exists). Probe `dev/mockups/conversations-probe.html?as=player|alias|left|gm|gmwatch&drive=1&contrast=1&panel=1&plus=1&new=1&w=&t=&p=` runs the REAL service + pane; `drive=1` presses real buttons and puts OK or the failure in the title; measured 0 text nodes under 4.5:1 on all three admin presets, the player theme and Arasaka. Stress macro `dev/tools/test-conversations-stress.macro.js`.
- **Storage:** one journal per conversation (flags `type:'conversation'`, members, `lastSeq`), ownership default NONE so it stays out of every sidebar. Lines live in page flags keyed by line id, written as single dot-path keys with `{render:false}`, `PAGE_LINES` per page. **Privacy is the same as mail: the UI hides, the data reaches every client** (the probe proved a page with no access still arrives). Don't add page ownership back. Read state + mute live on a USER flag (`conversationState`), so nothing redraws an actor sheet.
- **Rules are pure in `scripts/utils/conversations.js`. Writes go through ONE queue on the active GM** (`_request` → `_run` → `_apply`, `SOCKET_OPS.CONVERSATION_REQUEST/RESULT`); `seq` only goes up and `lineId` makes a retry idempotent. Lines wait on the client in localStorage with no GM or no signal, and flush on GM connect / network connect.
- **A member is an identity, fixed at Join.** Key = address (`memberKeyOf`); an alias member and its lines carry NO actorId. `spans` decide what someone can see (`canSee`), so added people see only what came after and removed people keep what they had.
- **Lines are plain text** (`lineText`), escaped wherever drawn. Pictures are paths or http(s) (`safeImage`, no data URIs). A shared contact is a card (`sanitizeCard` refuses a locked one and holds no owner); Save goes through `contactShareService._mergeExisting`, so it only adds what was missing. Nothing enters someone's contacts by itself.
- **`ConversationPane` is one class for both sides** (`admin` flag), built as strings. A new line APPENDS (`onLines`); typing, scroll and the New marker survive a window redraw (`snapshot` in the viewer's `_preRender`, `mount` in `_onRender`). **A paint replaces what is inside the host, not the host, so listeners go on once (`_wiredHost`).** The first build added them per paint and every button fired twice; only pressing real buttons found it.
- **Inbox:** rows merge with mail as `rowAsMessage` pseudo-messages (`isConversation`), split around `_enrichMessages`, excluded from `_lastPaginatedIds` and select-all. The list never redraws for a line (`_patchConvRow`). Mail filters that a chat can't satisfy (network, tags, sent, saved…) leave conversations out.
- **Notifications:** one keyed toast per conversation updated in place (`NotificationService.upsertToast`), one sound until read, none when open / muted / own line (`notifyPlan`). The badge counts conversations. The GM gets one combined toast, per-chat bell `conversationGmBell`, on for NPC chats.
- **Admin → Messages → Conversations** (`tabs/conversationsView.js`, nav after All mail): reading is invisible (`_read` returns in admin mode, nothing writes). `Speaking as` = one chip per NPC member, in the admin panel AND a GM's own inbox (`pane.gm`; `asKey` per chat, default the inbox's own NPC, else the last NPC to speak; Alt+1–9; typing and focus survive a swap). In a GM's inbox the chips also hold that inbox's own names, player or not (`_speakers`), because they opened it on purpose; the admin panel offers NPCs only. **`dialogBodyHtml`'s `field` is an object; a `<select>` goes in `extraHtml`** (a string drew an empty box, so Share silently cancelled). The probe now runs the real dialogs through a stand-in `Dialog`. Dates carry `data-day` and `_dedupeDays` keeps one per day however a line arrived; replacing a line (removal) never draws one. Removing a line deletes the words (`goneLine`).
- **GM Join as:** recent NPCs are chips (localStorage `ncm.conv.gmRecentNpcs`, `pushRecentNpc`, per GM client, dropped when deleted), `pickNpc` is a single-click picker (directory + NPC actors with no entry, never a player's main identity). The form starts on the open inbox's NPC. From the inbox the viewer then switches to that NPC's inbox (`inboxOwnerOf`).
- **Taps:** `NetworkService.tappersAt` → one running log page per conversation per tapper in their Exfil folder, no toast, `[picture]`, `[shared a contact: name]`. Taps only hear lines from the node's scene, like mail.
- **Purge + Orphan Audit** in ToolsTab; Factory Reset covers them (flagged journals, user flags). Not built: payphones, overheard extras.
