## Architecture: watching another player (2.1, 2026-11-01)

Tester: "a way for the group not opening the shard/terminal to view what's happening". `scripts/services/WatchService.js` (`game.nightcity.watchService`), `scripts/utils/watchMirror.js`, `scripts/ui/Watch/WatchWindowApp.js`, `templates/watch/watch-window.hbs`, `styles/components/watch.css` (`ncm-watch*`), `scripts/init/registerWatchSystem.js`, `SOCKET_OPS.WATCH`. Sim `dev/tools/sims/test-watch.mjs` (protocol), probe `dev/mockups/watch-probe.html` (real snapshot + mirror; title = OK or what leaked).
- **A window opts in with `static WATCHABLE = true`** (terminal, shard, node console) and gets an eye header button. World setting `watchMode`: `player` (default) · `always` · `off`. **A GM's own windows are never shared**: they show hidden accounts and GM controls.
- **It sends a copy of the window, not state to re-render**: a watcher often cannot load the item (a shard on another player's sheet), and a second live window would judge gates by the watcher's rights. `snapshotWindow` clones `.window-content` and carries scroll, visible input values and select picks; passwords, hidden inputs and file inputs stay behind. `cleanMirror` (both ends) strips ids, handlers, scripts, `javascript:` links and replaces media with a panel. Consoles and roll reveals mount inside the window, so they come along.
- Sending only happens with a watcher present (a MutationObserver plus capture listeners for scroll / input / change, which change the screen without touching the DOM). A joiner gets the whole picture (`snap`), then numbered `edit`s: `diffText` = one prefix/suffix splice of the HTML, plus the look only when it changed. Pacing: at most every 100 ms, slower when edits are big (200 bytes/ms) or the copy is slow to make. A watcher that sees a gap never applies it, it asks with `resync` (throttled). An edit over `MAX_PICTURE` = a note instead, and the next edit measures from what they have.
- **`mountMirror` updates the copy IN PLACE (`morphChildren`, by position), never `replaceChildren`**: surviving nodes keep their animations, loaded images and scroll, so the operator's own CSS animations and transitions run in the copy and none replay. Scrollers ease to the operator's position (`glideStep`). **`fitLayout` fills the watcher's window**: it shrinks only to fit the WIDTH, never for height (a tall window scrolls in `.ncm-watch__fit`; shrinking for height made a 560px-wide node console small and blurry), and the layout reflows into the rest, so there is never a gap (a watcher's layout can therefore be wider than the operator's). **It scales with CSS `zoom`, never `transform`**, which keeps text sharp. The bar's − / % / + buttons pick a size (`ZOOMS`, localStorage `ncm.watch.zoom`, per viewer); the window resizes itself to the operator's until the watcher resizes it. The copy wears the operator's classes, so watch.css pins `.ncm-app`'s `position: fixed` back, and the watch window's own content rule must stay `> .window-content` or it hits the copy's too. Only `.window-content` is copied, plus direct children of the window marked **`data-watch-overlay`** (the node console's `_flash`): an effect mounted on the app root needs that attribute or watchers never see it.
- **Not live-tested two-client.**
