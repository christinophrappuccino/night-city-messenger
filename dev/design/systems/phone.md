## Architecture: phone numbers, GM side (2.1, in progress, not live-tested)

Every write goes through CallService. `test-phone-gm-tools.mjs` fails on a control with no handler; `dev/mockups/admin-phone-numbers-probe.html` runs the real screens over the real service on an in-memory world.
- **Undo is a snapshot** (`phoneSnapshot` / `restorePhoneSnapshot`) and refuses if the world moved on since.
- **A contact shows only what was shared.** `numberForContact` never falls back to a directory entry or a linked character. An alias copy (`pushToPlayer`) carries no `actorId`. Players pass numbers with Share my number. Still open: `phoneLines` and call objects carry the owner, readable from the browser console.
- **`phoneSpecial` is an array** of `sanitizeSpecial` entries; anything else means the shipped TRAUMA + NCPD.
- **The call screen changes only by the type word, the company line, `data-ring` timing and the initials swirl.** Previews render the real `CallHud._callHtml`, never a copy.
- Dial an office extension as `MIL-0100 x17` (`splitExtension`).
- **`worldItemEntries()` has no `id`.** A multi `showNamePicker` keys on `id`, so every phone item list goes through `pickItems` (phoneNumbersView), which keys by name. Without it Done saved empty entries and the list reset.
- **Data Drop sends email, number or both** (`shareOptions.send`, shown only when the contact has both). Someone who already has the contact gets the missing part (`ContactShareService._mergeExisting`); nothing they have is overwritten.
- **The player's call log has tabs:** Calls · Missed · Voicemail · Contacts (`calls-filter`, `st.filter`, `logTabs`). Contacts = the phone book with search + Call. Before this no template offered `calls-filter`, so players could not reach voicemail.

## Architecture: what an emergency call says and looks like (2026-11-02)

Dev: GM-only editing, per person. Mock `dev/mockups/emergency-lines-mock.html`, sims `dev/tools/sims/test-emergency-lines.mjs` and `cdp-emergency-lines.mjs` (drives the real screens, needs the preview server). Not live-tested.
- **Words are slots (`BACKUP_SLOTS`, `TRAUMA_SLOTS` in `utils/phoneEmergency.js`), never literals in `EmergencyHud`.** Backup falls back person → organization → built in; Trauma Team has one set. `pickVoice` picks one line per slot ONCE per call, because a call redraws many times; `fillLine` fills `{place}` and the rest at display, and `{rounds}` reads "3 rounds". The die results, "you need N or lower", chat cards and the tracker's status words (`trackWords`) stay fixed.
- **`backup.people[actorId]` = `{ voice, look, img, groups }`**; organizations gain `voice` + `look`, Trauma Team `voice`. `sanitizeEmergency` builds these field by field, so a new field goes there too. No migration.
- **Their own groups:** `orgForPerson` puts them first, so at the same rank the default reaches for their own. Read it wherever a roll or picker needs the list, never `orgs[id].rows` directly.
- **`backupLook(kind, orgLook, personLook)`:** lights default by kind, and the default colour and arrival sound follow the lights. A colour must be `#rrggbb` because the tracker appends alpha to it.
- **The on scene banner goes through `arrivalFor`,** so a preview and the real arrival match. An active row keeps only the arrival's words, colour and sound (`voice` and `look` are stripped).
- **The GM always hears about a call:** `EmergencyHud` calls `svc.announce(info)` once the call really goes out (never on a preview or with no signal), and every GM gets `gmAlert`: a toast with a Live button and the `em-alert` tone, under the world setting `notifyGmEmergency`. It is separate from the chat cards, so a whispered roll still alerts. `announce` also posts ONE card for the table (`_callCard`, "Rache is calling for backup", world setting `emergencyChatCard`), which follows the caller's roll mode like the dice; later steps are not narrated in chat. Backup opens on `em-sting-backup`, rings twice (`call-ringback`), then `em-radio-in` when someone picks up. Sim `test-emergency-alert.mjs`.
- **Rounds run by themselves:** in combat, one per combat round; outside combat, `ROUND_MS` (6 s) on the active GM's clock (`tickRounds`, stops while the game is paused), and the team arrives when they run out. **Hold** on Live stops a team either way; -1 round, They arrive and Call off still work. The player's strip is a button that says what it means (`miniWhy`). Sim `test-emergency-alert.mjs`.
- **Editor (`phoneNumbersView.js`): one `emSlots` for all three.** Boxes write after a pause through `emPending`, and the click listener flushes before any button, so Play plays what was typed. `remember` also runs on a capture `scroll` listener, because a save re-renders the tab while someone types.

## Architecture: the phone logs at scale + emergency pictures (2026-11-02)

Dev-approved mock `dev/mockups/phone-log-folds-mock.html`. Sim `dev/tools/sims/test-phone-log-folds.mjs` (106). Not live-tested.
- **`scripts/utils/logFolds.js` (pure) is the one fold rule for long logs.** `dateBands`: Today, Yesterday, This week, one band per month for the past 12 months, one per year, measured on the GAME clock; a date ahead of the clock is Later, none is Undated. `namedGroups`: the same folds under names (a person, a mailbox), no day dividers, so the row carries the date. Only the newest starts open, a search or filter opens all, and the user's own fold wins (`bandShut`). A band shows `BAND_PAGE` (30) rows, then Show more, which replaced page numbers. A band's date field is `dateText`, never `sub` (a Handlebars helper).
- **Agent → Calls** (`buildLogRows`, `buildCallsContext`): search + Show + fold-all. **Search reads only what the character may see**: a contact's name, the number, the network, the reason, the words on their own calls. Folds are DOM-only so they animate; a search re-render restores the caret (`st.qFocus`).
- **Admin → Phone → Call log + Voicemail** (`logView`, `voicemailBoxes`, which still returns `boxes` for the nav count): one toolbar row, Filter holds Who + Network (ScopePickers, whose callback fires on open, so it compares) + Dates (DateRangePicker), active ones show as pills. By person, a call sits under both people.
- **Trauma Team calls use a special number** (`trauma.specialId`, default the shipped `TRAUMA`; `EmergencyService.traumaLine()`): its dialled key starts the call and its name, number and picture dress it. **Backup pictures**: `backupArt` = the group's `logo`, else the organization's, else none. Both show behind the trace in the frame and on the arrival banner. The ECG fades with `destination-out` so a picture behind it survives.
- **Emergency calls keep ONE scene for the whole call** (`EmergencyHud._open`, `_paint`, `_leave`; CSS `ncm-em-*`): an opening sting, a tracker beside the card (`_runTrack`), then an exit: the card uses the real call screen's `is-out` and the tracker folds. A step redraws only `.ncm-r5-em` and the subtitle, so the traces never restart and the card's entrance plays once. Never set `innerHTML` on the scene per step. `--ch-*` must be set on the `.ncm-call-hud` element itself, because its own rule redeclares them. The card sits at the normal call position and the words at the normal subtitle position. A normal end goes through `_leave`, an interruption through `_stop`. Reduced motion shows stills with no stings. **Pace (dev: it all happened too quickly):** `TRAUMA_BEATS` / `BACKUP_BEATS` + `organicBeats` (each gap loosened ±20%), rings before anyone picks up, the monitor starts on pick up; `EM_TIMES` and the stylesheet's durations must match (the sim compares them). **Backup is not always police** (dev): whoever a Lawman can call. An organization's `kind` picks the look (`backupLook`): only Police and Government get blue, red-and-blue lights and a siren; call words stay neutral. New sounds: `em-*` (`gen-call-sounds.cjs`, Sound Board). Probe `dev/mockups/emergency-probe.html?k=trauma|backup|arrive-tt|arrive-bk|normal&beat=0..4&art=&auto=1&still=1` runs the real code; headless does not advance CSS animations.
- **Corporate voicemail, sharing, audit, macros (same day):** `CallService._officeMailbox` (makes a send-only contact on first use, GM only); `ContactsTab._setKnows(…, { part })` + `_askShareWhat` (address / number / both); Orphan Audit `phoneOwners`; `messenger.placeCall` / `getOverheardCalls` / `startOverheardCall`.

## Architecture: payphones (2026-11-03, built, not live-tested)

Spec `dev/design/PHONE-REVISION.md` §Payphones "Decided 2026-11-03"; approved mock `dev/mockups/payphone-booth-mock.html` (three rounds, after the game screenshots `cyberpunk2077phone1/2.png` beside it — the layout and feel drawn our own way, never a trace; the PNGs are CDPR art and stay UNTRACKED). Sim `dev/tools/sims/test-payphones.mjs` (116, the real CallService + PayphoneService over mocked clients); probe `dev/mockups/payphone-probe.html?view=booth|admin|live` (live = a scripted run of the real controller, title OK).
- **A payphone is a world record** (setting `payphones`, `{ [id]: { id, number, name (the place), sceneId, look, condition, hear, help, range, sounds } }`, rules pure in `scripts/utils/payphones.js`) **plus a line in `phoneLines`** (kind `'payphone'`, type `'pay'`, nobody owns it; never written under an empty key). Saved looks: setting `payphoneStyles`. GM-only writes through `scripts/services/PayphoneService.js` (`game.nightcity.payphoneService`). A deleted scene removes its booths.
- **The call is CallService; a booth is a caller identity.** `placeCall(n, { payphone: id })` → `from = { name: 'Payphone, <place>', number, actorId: null, payphone, realActorId, realName, realUserId, wired }`. **`_send` masks each booth side per recipient** (`payphoneSendGroups` + `maskPayphoneSide`): real only for the GMs and the person on THAT booth (for a booth being called, whoever answered it) — the far end of a booth's call gets the mask (PRIV-02). **This is masking on screen, not secrecy (dev decision 2026-11-05, audit A6/PRIV-01):** module socket messages reach every connected client and each one only shows what is for it, so a player in the browser console could read who is on a booth or behind a withheld number — the same honest model as conversations. The `use` packet carries no `callId` any more (PRIV-03). **Wired**: no signal check, `net.id ''`, so no tap and no network activity row. Trauma Team from a booth still checks the caller's own plan (`selfId`).
- **A call TO a booth** (`line.kind === 'payphone'`) → `to = { kind: 'payphone', payphoneId, sceneId }`, ringing every active non-GM user VIEWING that scene (`_ringsHere`); out of order or nobody on the scene → rings out (no voicemail). **First pick-up wins, decided on the caller's client**: a second `answer` gets `'taken'`, and the caller confirms the winner to the GMs (`confirmed: true`, carrying only `answeredBy`); a GM remembers each pick-up's real details (`_ppAnswers`) and keeps the first until confirmed. `answer()` stamps `to.real*` (masked by `_send`) and narrows `to.userIds` to the answerer.
- **Logs**: a booth side writes to the GM-only journal "NCM — Payphone calls" (flag `payphoneLog`, `boothPage: true`, names read "V via Payphone, …"); nothing goes in the caller's own log; a player's page gets `maskPayphoneSide` copies. `writeLog` fills the answerer's real name from the GM's own copy (the caller never learns it). `allLogs` prefers the booth page; `payphoneLog()` / `logOf(id)`.
- **The ring on the scene**: CallHud ignores a booth's ring (`role callee && to.kind === 'payphone'`); PayphoneService plays the bell (Sound Board `payphone-ring`, or the booth's own file) every 1.7 s, pings its pins, and shows `.ncm-pb-ringnote` (Pick up live only in reach). **Who is on a booth** and **the speaker** go over `SOCKET_OPS.PAYPHONE` (`use` / `speaker` / `line`): the handset holder's client relays each call line, read-only, to the users with a token in reach (`bystanders`) — CallService's audience never widens.
- **The booth** = `scripts/ui/Calls/PayphoneBooth.js` (controller, body-mounted `.ncm-pb-host`, scales to fit, Esc / click outside = walk away) + `boothMarkup.js` (pure drawing; **every SVG id carries the booth's uid** — the admin preview and a live booth share a page) + `styles/components/payphone-booth.css` (`ncm-pb-*` booth, `ncm-pph-*` admin page; the booth wears ITS OWN colours via inline `--pb-*`, never a theme). It is for dialling and picking up only: OK hands off to the normal call screen, which stays untouched. Dial / key tones are Web Audio (the player's sound switch + volume); hook and chip are Sound Board ids. Look: style · colours · `--pb-grit` (tiers: rust ≥40, heavier ≥60, wrecked ≥85 = crack / flicker / dead 7) · `--pb-wire` (handset ≥10, hole ≥40, gutted ≥75 with sway + sparks; the hole ages with grit; a cursor torch lights hidden internals via an SVG mask) · three graffiti tags · screen text · stickers.
- **Access point kind `payphone`**: pins (`accessPayphone`, reach checked on double-click), step-on areas, links / macros / chat cards (open with `skipReach`). `openPayphonePlaceDialog` shares `askPlacement` with nodes. Factory Reset now clears every NCM pin + step-on Region; Orphan Audit finds dead payphone pins; Access points tab lists them.
- **Admin → Phone → Payphones** (`tabs/payphonesView.js`, string-built): list + editor + live preview; typing / sliders repaint the preview in place and save after a pause, buttons save and re-render. `openAdminTab('phone', { select: 'payphone:<id>' })`. Macros: `messenger.openPayphone`, `messenger.ringPayphone`; `game.nightcity.openPayphone(id)`.
- **Not live-tested.** In Foundry check: two players on one scene + a ring (first pick-up wins), the speaker strip for a bystander, a booth call from a dead zone, the bell on the whole scene, the pin's reach, Factory Reset with pins placed.

## Switches (stage 2, step 15, 2026-11-05)

Calls (`callsEnabled`, now `requiresReload`) and its three parts, Payphones (`payphonesEnabled`), Emergency lines (`emergencyEnabled`) and Overheard calls (`overheardEnabled`, all default ON), are features in `scripts/utils/features.js`; each part `requires: ['calls']`. Set in Module Settings or Admin → Phone → Settings (a change there calls `reloadConfirm({ world: true })`). The four services are always built in the `CallService` step; the screens / hooks / timers are separate feature steps in `registerCallSystem.js` (`Calls: call screen and live calls`, `Calls: emergency lines`, `Calls: overheard calls`, `Calls: payphones`), so `callHud` / `emergencyHud` / `overheardHud` / `payphoneBooth` are absent when their part is off (SERVICE_MAP marks them with `feature`, so the startup report does not call that a failure). Every call socket op is feature-tagged; the call requests are fire-and-forget, so an off part drops them. Entry points: `PayphoneService.open` says the booth is out of order, `OverheardService._ask` / `start` refuse, `EmergencyHud.trauma` / `backup` do nothing (GM previews still show), the Trauma number does not start the emergency flow, and the Agent's Calls tab hides the scanner / emergency buttons. Kept running when off: the number hygiene hooks (`deleteActor` / `deleteItem`). Not run when off: a deleted scene's booths stay on file (harmless; delete them in Admin → Phone → Payphones). Sim `test-features` §5; macro `dev/tools/test-s2-step15.macro.js`. Not live-tested.

## Tester round 2026-11-07 (Aegaeon; built, not live-tested)

Sim `dev/tools/sims/test-tester-round-2026-11-07.mjs`; macro `dev/tools/test-tester-2026-11-07.macro.js`.
- **A trace always answers.** `CallService._traceResult(from)` is what a successful trace finds: an owner line gives name + number, a place / label line its words + number, a burner (`trace: 'dead'` on a LINE TYPE, now labelled "The number only") the number only (`traceFinds` → `numberOnly`). Only a SPECIAL number set to a dead end, or a bare mask, gives null. `_revealTo` sends `reveal` with `dead` when null, and `_traceCard` whispers a "Trace result" card to the tracer + GMs (the old permanent toast could wait in Foundry's notification queue: the "minutes later"). The GM's live copy stores `tracedFrom`; `_send` gives masked recipients `tracedFrom` after a trace, never the whole caller (it used to send the real `from`, name included, for a burner too); `writeLog` / the page title use it for the callee's page.
- **The call log reads the call screen's rule** (`callsTab.shownOther(row, book, home, contacts)`): a contact matched like `savedContactFor` → their name and `addTo` (row button `calls-addnum` puts the number on that contact, confirming a replace); a line type that shows its name → the name and a pre-filled Save (`offerName` / `offerImg`). The log record keeps `showOnly` / `asLine` / `face` / `org`, and `img` only when the screen showed one (`_summary` `pick`).
- **Read-out / recorded greetings hold the tone until they end**: the service timer is `greetTimerMs` (60 s cap when it plays), and CallHud calls `greetingDone(callId)` when `speak()` (now resolves true/false) or the audio ends; when nothing plays, it falls back to the text estimate.
- **Looks right** is stored (`phoneFlagsOk`, a number setting).
- **Resize corner**: `BaseApplication._grabResizeHandle` captures the pointer on pointerdown (Foundry only captures on the first move, so a quick drag ending outside the window left its move listener attached).
- **Payphones**: Number → Change… (`askBoothNumber`: district select + 4 digits, the scene-named district first); Another stays in the booth's district; Call from it… (`callFrom`: the directory from `lines()`, or a typed number) places `{ payphone, gm: true }`, so `_caller` puts the GM on the booth as themselves.
- **Interface on a non-Netrunner** is still a Role Ability (`ROLE_ABILITY_NAMES` in SkillService): Rank Only = rank 0, no TECH.
