## Architecture: GM Admin Panel theme (separate from player theme)

The Admin Panel has its **own** theme, isolated from the player theme. The player `ThemeService` writes `--ncm-*` to `:root`; `styles/themes/admin-theme.css` re-defines the same `--ncm-*` variables **on any element carrying `data-ncm-admin-theme`** (`:is(.ncm-app, .ncm-admin-dialog)[data-ncm-admin-theme]`; the bare `.ncm-app.ncm-admin-panel` is kept as a robust default), which wins for every descendant (custom properties resolve from the nearest ancestor) — so each tagged window is themed in isolation and `:root` is untouched. **Don't move these overrides to `:root`** (that's the opposite of the player-theme rule) and **don't scope them tighter than the window root** or descendants won't inherit them.

**Carry-over to every GM tool (2026-09-10, tester: "Light theme, open Full Editor → still dark").** `scripts/utils/adminTheme.js` is the ONE stamping path. Rule agreed with the dev: **GM tools follow the admin theme + text size; player-facing immersive windows (message viewer, composer, shard viewer, terminal, Contact Manager, Theme Customizer, Program Deck) stay on the player theme even on a GM client.**
- **AppV2 windows opt in with `static ADMIN_THEMED = true`** (BaseApplication default false). `BaseApplication._onRender` calls `_applyAdminTheme()` right after `_applyAtmosphere` (stamps the attribute, forces scanlines/neon off, applies the text-size zoom + one-time frame resize via `_applyAdminTextScale`). Flagged: AdminPanelApp (and its pop-out AdminTabWindow), GMContactManagerApp [retired 2026-10-27], ActorImportPickerApp, ContactShareDialog, NetworkManagementApp [retired 2026-10-27], CreateNetworkDialog, TerminalConfigApp, ItemInboxConfig, DataShardComposer (its `_onRender` skips super, so it calls `this._applyAdminTheme()` explicitly — keep that), MalwareWorkshopApp. A new GM window = add the flag; a subclass that overrides `_onRender` without super must call it by hand.
- **Foundry v1 `Dialog`s can't inherit a window's vars (body-mounted), so GM code opens them through `adminDialog` / `adminConfirm` / `adminPrompt` / `adminWait`** (same signatures as `new Dialog` / `Dialog.confirm` / `Dialog.prompt` / `Dialog.wait`), which add the `ncm-admin-dialog` class; the `renderDialog` hook (`registerAdminDialogHook`, registerGMTools ready/111) stamps the attribute + zoom and grows the width once. admin-theme.css carries explicit chrome rules for `.ncm-admin-dialog[data-ncm-admin-theme]` (frame/header/content/inputs/buttons, `!important` against core + CPR). All ~80 GM-tool call sites were swept (AdminPanel tabs, GM Contact Manager, Role Manager, Terminal/Shard config, entry composer, Network Manager, Workshop, ShardSheetOverride, DateRangePicker; `showWorldItemPicker` passes `admin:true` while the player inventory picker stays plain). **A `new Dialog(` in GM-tool code is a bug** — grep for it. **Player-facing windows have their own wrappers (2026-10-21, tester: "pop-up windows still not resizing for text")** — `playerDialog` / `playerConfirm` / `playerPrompt` / `playerWait` (same file) tag `ncm-player-dialog`; the same `renderDialog` hook zooms those by the PLAYER's Theme Customizer Text Size (read live from `:root`'s `--ncm-text-scale-base`, saved `playerTheme.textScale` as fallback, clamped to the slider's 80–150) and grows the width once, with **no palette change** (a body-mounted Dialog keeps Foundry's look by design). **A dialog follows its OPENER**: when `document.activeElement` sits inside a `[data-ncm-admin-theme]` window (GM-view viewer/composer/contacts, a config sheet) the player wrapper tags it admin instead — the CyberTimePicker rule, now generic (the picker's own `activeElement` check is gone). The 30 raw call sites in the viewer / composer / Contact Manager / shard viewer / terminal / Theme Customizer / CyberTimePicker / `showNamePicker({admin:false})` were swept; **a raw `new Dialog(` / `Dialog.confirm(` anywhere in `scripts/` is now a dialog that scales with nothing** — `dev/tools/sims/test-admin-theme.mjs` (61 checks) walks the tree and fails on one (exempt: the wrappers and the namespace-migration prompt, which runs before the hook exists). Not live-tested.
- **Brand hex → `--ncm-*` sweep**: `node dev/tools/sweep-brand-hex.mjs [--check] [--only <selector regex>] <css…>` rewrites the literal brand palette (variables.css defaults: `#19f3f7`→secondary, `#2a2a45`→border, `#1a1a2e`→bg-surface, `#555570`→text-muted, brand `rgba()`→`color-mix`) to variables; it skips `var(--x, #hex)` fallbacks and non-brand colours. **The admin panel has ONE visual vocabulary — copy it, don't invent one.** Both new tabs (Security, Terminals) shipped feeling foreign and the dev flagged it as "the fonts look off… doesn't match the other tabs". It measured out as two objective inversions of the shipped convention, so check yours before adding a tab:
- **Fonts: display-dominant chrome, mono for VALUES ONLY.** `grep -o "var(--ncm-font-[a-z]*" styles/components/admin-panel/tab-X.css | sort | uniq -c` — the shipped tabs run display:mono ≈ **59:5** (contacts), 31:3 (shards), 49:21 (messages). The new tabs were **inverted** (security 4:19, terminals 2:14) — mono on buttons/labels/badges/titles, which reads as a different app. This is just the standing font rule (Rajdhani chrome, Share Tech Mono for *technical data values*) applied: a person's name = display, a machine/file/ID/timestamp/roll/count = mono.
- **Radius is 2px. Everywhere.** Shipped tabs: 28×2px (contacts), 23×2px (shards), 31×2px (messages), 32×2px (networks). The new tabs used 5–9px + a 20px pill — rounded reads as a foreign UI next to sharp neighbours. Badges are **1px**.
- **Copy these three, they are the reference implementations:** button = `.ncm-spam-send-btn` (display 11/700, uppercase, `letter-spacing:.04em`, radius 2px, `appearance:none`, `min-height:0`); badge/chip = `.ncm-ct-badge` (display 9/700 uppercase .04em, radius 1px); **checkbox = `.ncm-ct-row__check`** (outlined box, radius 2px, checked = faint `secondary` fill + a **cyan ✓**). Note the module-global `.ncm-app input[type=checkbox]` (base/interactions.css) paints a *solid cyan box with a dark border-tick* — right for the player UI, foreign in the panel; override it per-surface. **`--checkbox-size` does NOT work for this** — Foundry core declares that var ON the input, so a value inherited from a wrapping label loses; size the box directly and neutralise BOTH the module's border-tick geometry and core's layered FA-glyph `content:"\f14a\f14a"`.
- Section titles: display 11–12px/700 uppercase `.06em` (`.ncm-war-section__title`); hints: display 9px/500 italic muted (`.ncm-war-section__hint`).

**Admin CSS must use `--ncm-*` vars, not hardcoded brand values, or it won't follow the admin theme.** A 2026-06 sweep converted ~600 solid brand hexes → `var(--ncm-*)` and ~380 brand `rgba(r,g,b,a)` → `color-mix(in srgb, var(--ncm-X) N%, transparent)` across all `admin-panel/tab-*.css` (color-mix is fine in Foundry v12's Chromium). When adding admin-panel styles, follow that discipline. **Intentionally left hardcoded:** network-**type** colors (CorpNet blues etc.), per-preset icon colors, and black/white `rgba` (shadows/overlays — theme-agnostic). ## Architecture: the 2026-10-27 admin redesign — shared plumbing

Every admin tab was re-mocked (`dev/mockups/admin-*-redesign-mock.html`, dev-approved) and rebuilt in one pass; the build brief is `dev/design/ADMIN-REDESIGN-BUILD.md`. **Not live-tested.** The shared pattern: sub-tabs with count badges · list + detail · edit in place · Pop out. Plumbing every tab uses:
- **`tabAct`** — `data-action="tabAct" data-owner="<tab key>" data-op="<op>"` → `this.tabs[owner].onAct(op, event, target)` (`AdminPanelApp._onTabAct`). New buttons use this; do NOT add a static delegator per button. Older static actions stay where other code/sims still call them.
- **Pop out** — `popOutTab` (`data-tab`, optional `data-select`) opens **`AdminTabWindow`** (`scripts/ui/AdminPanel/AdminTabWindow.js`): the SAME AdminPanelApp class pinned to one tab (id `ncm-admin-pop-<tab>`, 1120×780, root `.ncm-admin-panel--pop`, context `isPopout`, chrome hidden, `dockTab` = back to the panel). Tabs widen under `.ncm-admin-panel--pop` in their own CSS; number-key tab switching is off in a pop-out.
- **`game.nightcity.openAdminTab(tab, { popout, select })`** (registerGMTools) — the ONE launcher; `select` goes to the tab's **`openTo(select)`** before render. `openGMContacts`, `openNetworkManager*` and the scene-control button all route here.
- **Scope picker** — `scripts/utils/scopePicker.js` + `styles/components/scope-picker.css` (`ncm-scope-*`; mock `dev/mockups/scope-picker.js`): a searchable chip + popover for any list of world things that can grow (networks, scenes, people, identities) — search, group chips with counts, "has activity", pinned rows, multi (checkbox/Only/Clear/Done) or single. - Each tab's context lives under ONE namespaced key (`ct2`, `net2`, `msg2`, `term2`, `shards2`, …) because AdminPanelApp spreads every tab's context into one object; heavy builds run only while that tab is active.
- Retired windows: **`GMContactManagerApp`** and **`NetworkManagementApp`** (+ their templates/CSS) are DELETED — folded into their tabs.

Compare against the current state and return early when nothing changed. **And the popover REPAINTS ITSELF on every change** (`changed()` → `rerenderPop`): the host callback re-renders its window, which replaces the BUTTON but never the body-mounted popover, so a multi-pick's rows kept stale checks until reopened (dev 2026-10-28: "selecting works but it doesn't appear checked"). ## Tools tab — Purge Messages (scoped) + Orphan Audit

Admin → Tools → Danger Zone → **Purge Messages** (`purgeMessages` action → `ToolsTab.onPurgeMessages`) is a **scoped** purge, not all-or-nothing. It enumerates targets — character + contact inboxes (via `MessageRepository.identifyInbox`, with per-inbox message counts) and data shards (via the `isDataShard` flag, world + actor-owned, counted by `DataShardService.getShardMessages`) — and presents a grouped `<select>` (plus an "ALL inboxes" option) in a `Dialog`; empty targets are skipped. A confirm dialog shows the exact count, then it deletes. `_purgeInboxJournal(journalId)` deletes only message pages (`flags.<MODULE>.messageId`) so the empty inbox survives; `_purgeShard(uuid)` removes entries via `DataShardService.removeMessage` so the shard item survives. Deletions fire the normal document-sync hooks, so open viewers update. (Read the select via `html.find(...)` in the Dialog callback — `FormDataExtended` is unreliable.)

**Orphan Audit** (`orphanAudit` → `ToolsTab.onOrphanAudit`, 2026-08-14) replaced the two dead Danger-Zone buttons: "Reset Module" (a double-confirm that ended in "not yet implemented") and "Rebuild Index" (called `repository.rebuildIndex()`, **which never existed** — optional chaining swallowed it and it reported success; don't re-add either without a real implementation). The audit scans for NCM data whose owner is gone — inbox journals whose actor/master-contact no longer exists (`_gatherOrphans` via `identifyInbox` + `masterContactService.getContact`), scene pins pointing at deleted terminal items (`flags.<MODULE>.terminalItemId`), and `traceHeat` entries keyed to deleted actors — lists them in a Dialog, and deletes/prunes on confirm.
