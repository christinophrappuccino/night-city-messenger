## Architecture: network authentication dialog

`NetworkAuthDialog` (`scripts/ui/NetworkManagement/NetworkAuthDialog.js` + `templates/dialogs/network-auth-dialog.hbs` + `styles/components/network-auth-dialog.css`) is the player-facing gate shown when connecting to a secured network **and now for terminal account logins** (via `showForAccount` — see the terminal Auth section; both go through the `SecurityAuthAdapters` source seam, so the dialog itself is source-agnostic). It's a **method-card** layout: Password / Skill Check / Key Item each render as a stacked card, **all visible at once** (so AND-mode can show every requirement). GM bypass (`gmBypass`) skips auth entirely — that's why solo-GM testing never sees the gate.

- **Two auth logics** (`network.security.authLogic`): `any` (OR — any one method grants) vs `all` (AND — every enabled method required). Derived in `_prepareContext`: `showPolicy` (banner only when >1 method), `progressLabel` ("Step X of N"), `activeMethod` (first incomplete card, AND only), per-method `passwordNum/skillNum/keyItemNum`, `showOrBeforeSkill/KeyItem` (OR dividers). AND-mode cards are **numbered ①②③** with `REQUIRED → PASSED/ACCEPTED` chips; completing one collapses it and advances the step counter (`_checkAuthComplete`). OR-mode cards are split by OR dividers, no numbers.
- **States the template must keep:** the Black-ICE danger panel (`isLethalICE` → pulsing red, shows ICE name/class/`formula`; `iceDealsDamage` from `failureMode==='damage'` drives the per-skill `⚠ fail = NdN to HP` warning), error banner (shake), key-item drop zone (browse + presented-item + wrong-item error), and the full **lockout** takeover (countdown + spent pips). Top accent bar color is set by `_onRender` via `data-auth-state` (password=gold, skill=purple, keyitem=cyan, **ice=red**, lockout=red).
- **Skill resolution goes through `SkillService` — never the dialog's old manual lookup.** The old code called `skillService.getSkillBreakdown`/`resolveSkillBonuses`, **which don't exist**, so it silently fell back to a buggy manual path (hardcoded INT for display; dropped the stat in the roll when the skill item wasn't matched → "total 3 with INT 8"). Now `_breakdownForSkill` uses **`SkillService.getSkillData`** (display) and the roll uses **`SkillService.performCheck`** (the canonical CPR path shared with shard hacking — posts the skill-check/"Network Bypass" chat card, handles crit/fumble/Luck). Both resolve identically, so display and roll can't disagree. Each skill **row shows its own stat+level** (`TECH 7 + Skill 4 → 11`); the breakdown grid renders only for single-skill networks (`showBreakdownGrid`), since it can only represent one skill.
- **Two skill-name footguns, both fixed in `SkillService._readSkillData`:** (1) **Role abilities** like **Interface come from the Netrunner role item, not a `type:'skill'` item** — `_readRoleAbility` resolves the rank from the role (main ability / sub-abilities / role name / `interface→netrunner` fallback). **The CPR data model stores `system.mainRoleAbility` as a STRING ("Interface") with the rank in `system.rank`** — the lookup only handled an `{name, rank}` object, so Interface resolved only when the role item was literally named "Netrunner" (fixed 2026-10-29, dev: "not detecting my player's Interface rank"; checks in test-jack-in §7). This matters everywhere Interface is the default breach skill (shard hack, contact breach, message decrypt). (2) **Name matching is space/punctuation-insensitive** (`_normSkill`) so a config value like `"Electronics/SecurityTech"` resolves to the actor's `"Electronics/Security Tech"` item. Stat linkage falls back to `SKILL_MAP` when neither item nor role supplies one. **On save**, network configs canonicalize typed skill names via `canonicalizeSkillName()` (constants.js — normalized → proper `SKILL_MAP` key) so newly-stored data matches CPR item names; the read-time normalization covers legacy data. Interface is rolled as **TECH + Interface-rank + d10** per the existing `SKILL_MAP` (intentional module choice, not RAW Interface-only).
- **CSS gotcha (bit us):** the Foundry button reset must be scoped to the inner **`.ncm-auth-dialog`**, NOT the bare `.ncm-network-auth-dialog` root — a blanket `button` reset also hits the window-frame **close (✕) control** and breaks its FontAwesome glyph. Button visual props need `!important` (Foundry + the CPR system both style buttons aggressively). The dialog is non-resizable, so `.window-content` has `max-height: 82vh; overflow-y: auto` + a styled scrollbar so a tall AND-mode dialog can't run off-screen.

## Architecture: NETWORK NODES — networks as access points (2026-10-29, all five steps built)

Design + decisions: `dev/design/NETWORK-NODES.md` (rounds 1–2, the console-ticker note, counterplay). Mocks: `dev/mockups/network-nodes-mock.html` (round 1, record), `network-nodes-v2-mock.html` (console / session / rules / scale / topology / timeline), **`network-nodes-jackin-mock.html`** (the APPROVED jack-in: a three-ring lock, one ring per layer clicks into a slot, the last ring is the roll with a stall + heartbeat, IN splits the lock and blooms the network, MISS grinds red + ICE; cyberpunk pass = hex rain, radar sweep, ring text, yellow hazard accents, chromatic split + glitch on every click; **tailor it to the content**: rings = the node's real layers, text from the node/network, the bloom = the network's real nodes). Build order: ① nodes + the scene rule (BUILT) → ② the node console (BUILT) → ③ Jacking in rules + the breach (BUILT) → ④ session actions (BUILT) → ⑤ infection (BUILT).
- **A node is a physical thing on a map that carries a network into a place** (router / relay / mast / junction / antenna). Stored in the hidden world setting **`networkNodes`** `{ [nodeId]: node }` (`{id, networkId, name, kind, sceneId, place, state: on|off|jammed|damaged, jammedUntil (game ms), hidden, discoverable, alert 0..3, showTraffic, flavour[], security, override, log[]}`). Pure rules **`scripts/utils/networkNodes.js`**: `sanitizeNode`, `nodeStateAt` (a jam whose time passed reads as on at once), `sceneVerdict` / `cutNetworks` / `carriedNetworks`, `statePatch`, `appendLog` (cap 40), `nodeHex` / `nodeFirmware` (display flavour off the id), `expiredJams`.
- **The scene rule (v1, scene-level):** a scene with nodes for a network gets that network only while ONE of them is up; an up node also CARRIES its network onto a scene it was never wired to; a scene with no nodes behaves exactly as before (nodes are optional — a world without any sees no change). Enforced in ONE place, `NetworkService.getAvailableNetworks` (cut → removed, carried → added), so every selector / composer / auth path follows.
- **NetworkService node API:** `getNodes({networkId, sceneId})`, `getNode`, `saveNode` / `deleteNode` (GM), `setNodeState(id, state, {minutes, who})` (GM writes + a log line; a player relays via **`SOCKET_OPS.NETWORK_NODE_REQUEST`** → `handleNodeRequest`, one GM; no GM online → refused with a reason), `reapNodeJams` (GM, every 30 s). **Every client re-applies the rule to its own connection** (`_reevaluateNodes`, on the setting's `updateSetting` hook, `updateWorldTime` and scene change): on the cut network → moved to another that still reaches with a "signal lost" toast, or into the dead-zone path (`_nodeDead`) when nothing reaches so queued mail waits; when it comes back → returned to it ("is back"). The hook also emits `NETWORK_CHANGED {type:'nodes'}` so open windows refresh.
- **Admin:** Networks → All networks → a network's detail has a **Nodes** section: per-scene verdict pills (red = every node there down, green = n/m up), a row per node (kind icon, name, Hidden tag, hex · kind · scene link · place, the state in its meaning colour, Switch off / Jam (themed prompt, minutes) / Switch on / Edit / Remove), **Add a node** → `scripts/ui/NetworkNodes/NodeDialogs.js` (`editNodeDialog` — the placement dialog's look: name, kind, scene via the picker, where on it, Hidden / Discoverable / Show traffic, flavour lines for the console ticker; pure `nodeEditHtml` / `readNodeEdit`). Ops `nodeAdd/nodeEdit/nodeState/nodeDel/nodeScene` via `tabAct`; rows carry `netId`/`netName` (no `../` in that block). CSS `ncm-net2-node*` (tab-networks.css), `ncm-nde*` (ncm-dialog.css). The preview `admin-networks-preview.html?view=all&sel=NCPD` carries five sample nodes (`?nodes=0` hides them).
- **Live-test round (same day):** the state pill IS the on/off switch (`nodeToggle`); the dialog's kind is five equal icon tiles (`ncm-nde__kind`, the wrapped segmented row was jumbled) and the three switches are cards with a toggle (Hidden in the secret colour). `_reevaluateNodes` acts only when a signature of (scene, cut set, carried set, current network, dead state) changes — it had been re-running on every `updateWorldTime` tick of a live clock; the world-time hook now only runs while some node is jammed; AdminPanel treats `NETWORK_CHANGED {type:'nodes'}` as a refresh, never a "switched to Unknown" activity row. Kind is flavour today (icon, firmware name, later the jack-in rings) — no rules difference. Probe `admin-dialog-probe.html?nde=1`.
- **The GM is moved too, and machines follow (2026-10-29, dev: "I jammed it and I'm still on it in the messenger"):** the GM exemption added during the flicker fix is gone — the GM's own connection follows the scene like a player's (the signature guard is what stops the repeat; the GM still sends from anywhere via the composer's VIA override, and dead-zone queueing is player-only). **A terminal's uplink over a cut network is LOCAL ONLY on the viewed scene** — `TerminalService._nodeCutsUplink(networkId, wired)` inside `getUplink` (returns `{networkId:null, network:null, cutNetworkId}`); a WIRED interface rides out a jam (radio) but not a node switched off or damaged; an open terminal re-renders on the `networkNodes` setting hook (`_onNodesChange`, removed in close()). - **Jammed networks in the selector + Unjam (same day, dev):** a network a node is cutting on the viewed scene is its OWN row in the inbox network selector (state `jammed`, striped amber, a chip "Jammed · 18m" / "Node down" / "Node damaged" with its icon, sorted last, left out of the "N available" count; clicking it says why instead of connecting) — `sceneBlocks(all, sceneId, now)` (utils/networkNodes.js: jammed wins, then damaged, then off; until = the last jam to end) via `NetworkService.getSceneBlocks()`; `isNodeDead` lets a node-made no-signal still list the networks (the partial keys its dead-zone panel on the new context flag `selectorDead`, never `isDeadZone`). ## Simple network mode (stage 2, step 17, 2026-11-05)

- **Switch:** Module Settings → **Network simulation** (`networkSimulationEnabled`, world, default ON, `requiresReload`). Off = simple network mode. In `scripts/utils/features.js` it is the `networks` feature. Dev decisions: reload (not instant), nodes go off with it, everyone sits on CitiNet (no network picker setting).
- **One place:** `NetworkService.simple` (`!isFeatureOn('networks')`). The public answers honour it: `currentNetworkId` → CITINET, `isDeadZone` false, `signalStrength` 100, `isNodeDead` false, `getAvailableNetworks` → [CitiNet], `canAccessNetwork` only CitiNet, `isAuthenticated` true, `getMessageAccessControl` null, `satisfiesMessageAccess` true (old restricted mail opens), `canSendToNetwork` allowed, `getReachableNetworkIds` every network, `checkAccess` / `networkPasses` pass (shard and terminal network gates, tethered too), `checkReliability` true, `tappersAt` [], `switchNetwork` refuses anything but CitiNet (`reason: 'simple_network'`). The constructor skips the scene hook (`canvasReady` network switching / dead zones) and the node hooks (re-evaluation, node reapers). The 50-odd callers are unchanged.
- **Edges:** the node console refuses to open (players: "There is nothing to connect to here."; GM: names the setting). `NETWORK_NODE_REQUEST` is feature-tagged (dropped). A GM dead-zone toggle's broadcast is ignored. Admin → Networks shows a band. Network and node data are kept and edit as normal.
- **Registry change that came with it:** each FEATURES entry carries `default` (= the registered default, checked by `test-features`); an unset or unreadable setting answers that default instead of "off" — otherwise a mock (or any read before registration) would flip a world into simple mode.
