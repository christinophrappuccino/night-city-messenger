## Architecture: the boot splash (the Monogram Etch)

**`scripts/ui/BootSplash.js` — `playBootSplash()`.** The mark that plays on the FIRST inbox open of a page load (`openNCM` guards with `_hasBootedThisSession`, so a reload is the only way to see it twice). A ~520px **panel** opens from a scanline sliver, the three letters are drawn inside it as open SVG strokes, a scan sweeps down and leaves them solid, a rule draws outward from the centre, and NIGHT CITY MESSENGER unfolds beneath it. **The accent is the SECONDARY slot (brand cyan), not primary** (dev: "make the red accents the blue") — primary is the machine-identity red and a boot flourish in alert red reads as a warning at a glance. The scan stays legible on top of it by being the same hue pushed toward white (`color-mix` with a literal fallback declared first), rather than a second colour competing with the accent. **It is a window, not a takeover** (dev, second round): a boot flourish that blacks out the screen reads as an error state, so there is **no scrim at all** (dev, third round) — the panel carries its own ground and its own glow, the scanline film sits on the PANEL rather than the desktop, and the table keeps looking at Foundry while it plays. Darkening a screen the splash deliberately does not block would be a lie about what is usable. A header strip carries the identity, a segmented meter and the state chip (Etching → Set) so the mark itself never has to. The header's bottom edge IS the progress line — one hairline doing two jobs. Corner brackets are inset 5px and the header and footer are padded to 22px to clear them; at 14px the text ran under the marks and read as a mistake. It replaced the icon + title + percentage card; the dev picked it from five concepts in `dev/mockups/boot-splash-concepts.html`, which stays as the record of the options.

- **The animation is ONE deterministic `paint(p)`, p = 0..1, fed by rAF** — not a pile of CSS delays. That is what makes reduced motion "paint(1) and stop" rather than a second look that can drift, lets any frame be frozen for review, and puts the pace in ONE constant (`DURATION_MS`) with the beats as fractions of it in `STAGE`. The sim asserts the stage windows stay inside 0..1, never invert, and never run backwards.
- **A wall clock finishes it, not just the frame loop.** `requestAnimationFrame` stops dead in a hidden tab and can be throttled to nothing, and **`openNCM` awaits this promise before opening the inbox** — so a stalled loop would leave a splash on screen with no Agent behind it. `capAfter()` arms a `setTimeout` for the whole run; whichever lands first wins, because `finish()` is idempotent. Headless found this: under `--virtual-time-budget` the rAF loop never completed and the overlay was still in the DOM at 45s.
- **Each splash gets its OWN clipPath id.** An SVG `clipPath` is addressed document-wide, so two splashes on one page both resolved to the first one's clip and the second never filled in. `splashMarkup()` mints a fresh id per call rather than trusting there is only ever one on screen.
- **It is body-mounted, so every colour carries a hard fallback** (`var(--ncm-primary, #F65261)` and friends) — there is no `.ncm-app` ancestor to inherit from if the player theme has not written `:root` yet. Same rule as the chat cards.
- **`pointer-events: none`.** A splash is a flourish, not a modal; an overlay that eats clicks can hold the table hostage if anything goes wrong.
- **`FADE_MS` and the CSS transition on `.ncm-boot-splash.fade-out` are two halves of one timing** — the JS removes the node after the fade, so they must agree. The sim reads the number out of the stylesheet and compares it.
- **Motion is vetoed, never raised:** the module's animation preference (`themeService.getAnimationLevel()`) and the OS `prefers-reduced-motion` can each force the still frame; neither can turn motion back on. The wrapper in `registerMessagingSystem` answers only those two Foundry questions (may we move, what version are we) and hands off.
- Why it is a module rather than a function inside `registerMessagingSystem`: so **`dev/mockups/boot-splash-preview.html` imports the REAL thing** (play, scrub to any `?t=`, three frozen frames, the reduced path) instead of a hand-copied lookalike that drifts from what ships. Sim: `dev/tools/sims/test-boot-splash.mjs` (19 checks).

## Architecture: the minimize button (2026-10-29)

Dev: "the admin panel needs a minimize option along with all the popups … cyberpunk-like but mostly clear". Most NCM windows were already `minimizable` — by double-clicking the title bar, which nobody knew. `scripts/utils/windowMinimize.js` (`registerMinimizeControls`, registerUIComponents init/21) adds a visible button beside the ✕ from TWO hooks, no per-window code: `renderApplicationV2` (Foundry fires `render<Class>` for every class in the chain) for every `ncm-app` frame with `window.minimizable`, and `renderDialog` for the bigger v1 dialogs (`ncm-themed-dialog`, `ncm-pkr-dialog`, `ncm-rmgr-dialog`, `ncm-time-config-dialog`, `ncm-ap-dialog`) — **never a yes/no confirm** (`themedConfirm` adds `ncm-dlg-confirm`). Pure `wantsMinimize` / `minimizeFace` (a centred `fa-minus`, NOT `fa-window-minimize` whose bar sits low and reads off-centre; `fa-window-restore` when rolled up). A MutationObserver on the frame's `minimized` class keeps the glyph right after a title-bar double-click; the button swallows its own dblclick and carries NO `data-action` (Foundry would look for a handler). Now minimizable: Configure Shard, the entry composer, Configure Terminal, Create Network. **Deliberately not:** the network login dialog, the dead-zone warning, email setup (mid-flow). CSS at the end of `styles/base/window-chrome.css` (`.ncm-minbtn`: window tokens, corner brackets + glow on hover, a rolled-up window gets a 3px accent strip on its title bar). Sim `dev/tools/sims/test-window-minimize.mjs` (21). Not live-tested.

## Architecture: sound feedback

All audio goes through `SoundService.play(id, {volume,loop})` (IDs in `SOUND_PATHS`), which gates on the `soundEnabled` pref and scales by `soundVolume` — that one NCM slider governs **everything** below.

**UI interaction sounds are centralized in `BaseApplication`** (every NCM window extends it) — do **not** sprinkle `play('click')` in handlers (that drifted inconsistent; the manual calls were removed). Wired once via `_wireUiSounds()`: a document-level **capture** listener with a `this.element.contains()` containment guard (element-level listeners are unreliable in Foundry), torn down in `close()`. So only the window containing the event plays, and capture means a handler's `stopPropagation` can't swallow it. Coverage: `click` on actionable controls (`button, [data-action], a[href], [role="button"], .ncm-clickable`), `open` (first render), `close`. `EmailSetupFlow` extends raw `ApplicationV2` and is **not** covered.

**The GM can replace any sound — Admin → Tools → Sounds (2026-10-29).** `scripts/utils/soundCatalog.js` (pure) is the catalogue: `SOUND_INFO` gives every `SOUND_PATHS` id a name, a group and plain words for where it plays (keystroke / queue-flush / terminal-hum are honestly "not used yet"; the sim checks with git grep), and `soundSource(id, overrides)` is the ONE answer to what plays. World setting `soundOverrides` = `{ [id]: { src, volume 0.1–2, off } }` (sanitized: audio files only, no script/data urls). **Every play path reads it** — `SoundService.source(id)` feeds `play`, the varied Web Audio player (clicks, terminal sound sets, which remap onto ids and so pick up replacements too) and the preload; an `updateSetting` hook drops the cache on every client. `SoundBoardApp` (`scripts/ui/Sounds/`, `templates/sounds/sound-board.hbs` = `TEMPLATES.SOUND_BOARD`, `styles/components/sound-board.css` `ncm-sb-*`; ADMIN_THEMED, minimizable; `game.nightcity.openSoundBoard()`): grouped rows with ▶ (`preview`, plays even with sounds off), Browse (Foundry's audio FilePicker, which uploads), a per-sound volume %, Off, Reset; search + Changed filter, Export / Import JSON (`{ncmSounds:1, sounds}`, the files themselves are not included), Reset all. A replacement plays for everyone, so the file must be somewhere players can load. Sim `test-sound-board.mjs` (36).

**There is no hover SFX** — it was deliberately removed (the `mouseover` listener, the `#uiHoverHandler`/`#lastHover` fields, and the `'hover'` entry in `SOUND_PATHS` are all gone; `assets/sounds/ui/hover.ogg` lingers unused). Don't re-add a hover sound. CSS `:hover` styles and hover-*preview* UI logic (trust segments, date-range picker) are unrelated and stay.

**The click is varied + quiet** via `SoundService.playClick()`: base `CLICK_GAIN = 0.25`, plus per-press random pitch (playback rate 0.94–1.06) and volume jitter (0.85–1.15×) using a one-shot Web Audio buffer source (the click `.ogg` decoded once + cached), so repeats don't sound identical. Falls back to `play('click', {volume})` if Web Audio is unavailable. `soundVolume` is baked into the gain so the slider still applies. Tuning knobs: `CLICK_GAIN` + the jitter ranges in `playClick()`. The same Web Audio path has a public face — **`SoundService.playStyled(id, {volume, rate})`** — used by the per-terminal sound sets (see the terminals section) to re-pitch existing assets; rate 1 short-circuits to the standard player.

**Shard/security outcome audio: the animated UI owns the climax, not the service.** `DataShardService.attemptHack` and `validateKeyItem` accept a `silent` option; the `ItemInboxApp` calls that drive an animation pass `silent: true` so the service skips its immediate result sounds (which otherwise fire ~6s early / double the animation). The breach sequence (`_playHackSequence`) plays `hack-start` → `hack-progress` (scan + inject) → at the climax `hack-success` **or** `hack-fail` + `black-ice` (on damage) + `lockout` (on lockout); the key-item accept splash plays `key-accepted`, the reject shake plays `key-rejected`. **Non-animated / macro-API callers leave `silent` off and keep the immediate sounds** (`silent` also threads into `_applyBlackICEDamage` → `ICEService.applyDamage`). The **"Shard Unlocked" splash plays `shard-decrypt`** — deliberately distinct from `hack-success` (which is the dice-roll climax, not the shard opening). The 5 once-orphaned sounds are now wired: `hack-start`/`hack-progress` (sequence), `shard-compile` (encoding overlay), `shard-expire` (`_destroyShard`), `trace-fire` (`NotificationService.showShardTrace`).
