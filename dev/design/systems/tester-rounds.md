## Tester round 2026-10-27 — Send As identity, per-skill bypass DVs, gate skills

Sim `dev/tools/sims/test-tester-2026-10-27.mjs` (54). **Not live-tested.**
- **Send As sent from the OLD address after an NPC moved to a new main identity.** Admin → Contacts **Send As** passed only `fromActorId`, so the composer fell back to the actor's registered `email` flag, which nothing ever moved. Now: **every Send-As door passes `fromContactId`** (Admin → Contacts, the GM Contact Manager's Send As, Admin → Messages → Send as NPC — the GM Contact Manager one was missed in the first pass and was what the tester clicked; the sim greps all three for a bare `fromActorId: contact.actorId`); `MasterContactService._syncActorEmail(actorId)` rewrites an **NPC's** flag to its main identity's address whenever the main is starred (`setPrimaryIdentity`) or its email/actor/primary changes (`updateContact`); and `_senderEmailFor` / the composer's `_fromEmail` let a STARRED (`primaryIdentity`) main beat a stale flag — **NPCs only**: a player character's address is the player's Email Setup choice and is never rewritten or overridden.
- **Sender portraits follow the identity** (same round): the composer From avatar + reply quote card (name/address/portrait from `orig.fromContactId`), the Agent viewer sender avatar (an alias never falls back to `fromActor.img`, nor to a player contact that saved the main face), the terminal viewer (`_senderPortrait(msg)`: `fromContactId` → directory by address → actor) and the Messages → Send as NPC chips (one chip per IDENTITY now, own portrait via `resolveDisplayPortrait`) all go through the alias-safe resolvers. The composer's Send-as list lights only the picked identity.
- **Per-skill bypass DVs — `scripts/utils/bypassSkills.js`.** The shared SECURITY_BLOCK (networks + terminal accounts) gains an optional `bypassSkillDCs: {skill: dv}`; **`bypassDCFor(sec, skill)` is the ONE read** (space/punct-insensitive name match, falls back to `bypassDC` — no migration). `bypassFieldsFrom(rows)` writes `bypassSkills` + the map + `bypassDC` = the first row's DV (so a missed single-DV reader still sees a sane number). Editor = `bypassRowsHtml` / `wireBypassRows` / `readBypassRows` (unnamed inputs, `[data-bypass-rows]`, CSS `styles/components/bypass-skills.css`, `ncm-bypass__*`) in the Network Manager editor and the terminal account editor. The auth dialog shows each row's own DV and a range in the header (`bypassDCLabel`). Shards are separate (`config.skillDCs`, long-standing). The terminal quick-entry console still rolls the FIRST skill only.
- **Operator Access role picker did nothing** — `onGateAddRole` looked for `[data-role-chips]` inside a gear OR-group (`.ncm-sec-admin-gate__grp`); the Role block is a `__req`. Fixed, and `_appendChip` clears the "no role required" placeholder.
- **Gate skills are a LIST** — `gate.skills: [{name, min}]`, ANY one qualifies, each at its own rank; the legacy single `skill` is read as a list of one (`gateSkillsOf` in helpers.js for `canOperate`; `sanitizeGate` folds it into `skills` and clears it). Security tab = skill rows (`_gateSkillRowHtml`, actions `securityGateAddSkill`/`securityGateRemoveSkill`); the Player Authoring card edits `gate.skills.N.*` (`gateSkillAdd`/`gateSkillDel`).
- **World setting `roleAbilityRoll`** (Module Settings, default `stat` = unchanged): `rank` rolls a role ability (Interface) as rank + d10 — `SkillService._readSkillData` zeroes the stat (`statName: none`) for role abilities only, via `SkillService.roleAbilityRankOnly()`.

## Tester round 2026-10-29

- **Scheduled messages (tester CptWashu: "a scheduled eddies payment fails, even from the GM; unscheduled it sends")** — `SchedulingService.scheduleMessage` demanded a sender ACTOR and a recipient ACTOR, so a GM paying from an NPC directory contact (or sending to a contact / several people / a group) failed only when scheduled. It now accepts what an immediate send accepts. A player's schedule was never saved (only the GM can write `scheduledMessages`; the GM held it in memory until a reload) — the player now hands it over and the active GM saves add / cancel / edit; with no GM online the player is refused with a reason (the composer refunds the eddies). Delivery is the active GM's alone (`_isDeliverer`; two GMs used to deliver twice) with an overlap guard. Sim `test-scheduling.mjs` (16).
- **Terminal Reset did not unlock a timed lockout** — `SecurityService.resetAllForTarget` cleared only the GM's own in-memory state; the lockout lives on the PLAYER's client (and a mirrored copy in `_remote`). It now clears both maps for every actor on that target and broadcasts `SECURITY_CLEAR` with `actorId: '*'` (`receiveClear` → `_clearTargetLocal`); every caller (terminal Reset, shard relock, network reset logins, the skeleton-key program) meant "for everyone". Sim `test-lockout-reset.mjs`.
- **Search boxes jumbled typed text** (Contacts, and the same race in every admin tab) — typing re-renders the tab and the render REPLACES the box; keys typed while it was in flight were lost and the caret jumped. `AdminPanelApp._preRender` now records the focused text box (selector from its own data-* attributes) with its live value + caret, `_restoreTyping` (end of `_onRender`) puts both back and, if the box moved on during the render, fires one `input` so the tab re-filters. A new admin search box needs nothing.
- **Mark unread**: the Agent viewer has an Unread button on an open message (`mark-unread` → `MessageService.markAsUnread` → repository; back to the list so it is not re-read); Admin → All mail's action row has a Mark read / unread toggle (`mailReadToggle` → `MessagesTab._setRead`, writes the page directly — contact inboxes have no actor).
- **Terminals → + New ▾** (Blank terminal `newBlank` · Convert an item… `import` · Import from JSON… `importJson`, reads `{ncmTerminal}` or `{ncmTerminals}`; `TerminalsTab.parseTerminalImport`); the rack groups fold with an animation (`_toggleGroup` shrinks the live rack, `_growOpened` grows a new one; reduced-motion skips).
- **Shards already export/import** (Export on the header, bulk Export in Select, + New ▾ → Import JSON) — the tester was on the old panel.
- **Security → "Terminal operator access"** (was "Operator access") with a lede naming Upload / System Sweep and the countermeasure-expert use.
- **Networks → Scenes**: `createScene/updateScene/deleteScene` hooks re-render the tab while it is on screen (a new scene's thumbnail is generated after creation); the Paint strip is ONE row that scrolls sideways (`.ncm-net2-attx__row`), paintable networks first and globals last, a Find box past 8 networks (DOM-only). **Activity log rows carry the scene** (`NetworkAccessLogService` stamps `sceneId`/`sceneName` from the acting user's viewed scene; searchable).
- **Overview → Guide** button at the top of the dock opens `docs/NCM-Getting-Started.pdf` (now shipped; build-zip allows a PDF under docs/ only). The PDF predates the admin redesign — re-export it before the next release.
- **Heat → Adjust** dialog rebuilt (`.ncm-heatadj`, tab-security.css): live number + tier word in the tier colour, a banded slider, −10/−5/+5/+10/Clear steps, a labelled reason, tell-the-player; names are escaped now.
- **Terminal navigation made obvious** (two testers: "how do I move?"): the TTY layout has a clickable folder bar (`.ncm-tmtty__nav`: every folder as `name/ count`, the open one lit, then mail | files), clickable footer folders and clickable `m` / `f` / `?` hints (`terminalTtyCmd` runs the same command as typing). Every command runs on Enter or the ⏎ button (`data-tty-run`); the placeholder says so. (Single-key hotkeys were tried and dropped at the dev's call.) **The TTY controls live at the TOP** (`.ncm-tmtty__top`, outside the scroller): the folder bar, then a BOXED "Type here" command line (`label.ncm-tmtty__in`, focus glow) that takes focus on every render unless something else in the window has it — testers "don't see where to type": the prompt used to be an unboxed transparent line at the bottom that could also fall below the window. A `<label>` there needs `text-transform:none` (the module-wide `.ncm-app label` uppercase rule). The GM "Move to…" select in the message/file header is now a **Move ▾** menu (`details.ncm-term__move[data-move-root]`, items `terminalMoveTo` with `data-folder`, icons, "here now"; outside click closes, `_moveCloser`), and a GM can **drag any row onto a folder** in every layout (`_wireDragMove`, its own drag type `application/x-ncm-terminal-message` so canvas / Item Piles drop handlers never see it).
- **Terminal errors are now said out loud**: `action()` (every viewer button), `_prepareContext` (→ `_buildContext`) and `_onRender` (→ `_onRenderInner`) catch and toast "NCM | Terminal: …" — testers saw "clicking does nothing" with no console open. **Open:** the cause of that dead-click report is still unknown; the next live test should show the toast.

## Tester round 2026-10-30

- **"Restrict to specific networks" on a terminal entry reverted (tester CptWashu).** Both terminal edit doors built their own edit data and left out `networkVisibility`; the edit path writes entryData straight to flags, so re-saving wiped the restriction (the viewer's door also dropped `folder` + `status`, so an edit moved mail to the Inbox). **Every terminal edit door now uses `DataShardComposer.terminalEditData(raw)`; a new message field goes there.** The picks live in `_netDraft` (`_netState` / `_setNetDraft` / `_paintNetworkTags`), so a re-render can't lose them; picking a network adds it and ticks Restrict (the + button is gone); removing the last one unticks it; `[data-net-note]` warns when Restrict has no networks, or when the terminal has no Machine Uplink interface on a picked network (players could then never reach it). `.ncm-tag` had no CSS outside the auth dialog, so the tag rendered as a bare name over a Foundry button. A GM always sees a restricted entry, tagged OFF-NET; test as a player. Not live-tested.
- **Network Reachability (the terminal's Layer 0 gate), same day.** Configure Terminal → Network offers **Any network / Only these networks** (`_wireReachability`: the list hides under Any, and an empty list warns). `type` is gone from this sheet because it had no editor and locked everyone out; a stored `type` / `both` reads as Only these and becomes it on Save, and `terminalReachRule` (helpers.js) already enforces a `type` with no types that way, so no re-save is needed (types set by a macro still work). Stored `any` terminals with networks ticked are deliberately NOT converted (that could lock players out mid-campaign). **Signal threshold is gone from the terminal sheet** (the check only runs for a tethered connection, which terminals can't be). `NetworkService.networkPasses(netConfig, network)` is the ONE mode rule behind `checkAccess` and the gate's statuses. Gate: names every allowed network, "secured" is real, only a network that would let you in is clickable, and a click goes through `connectToNetwork` (so a secured one opens its login dialog; a refused switch says why). `_recheckGate` lifts the gate on `NETWORK_CHANGED` and on an item update. **The gate is only checked on the way in: leaving the network never logs anyone out** (dev decision). Shards: a Min Signal of 0 now stays 0. Network Spoof still has no authoring UI, so its button never shows. The account editor's Network-gated row warns the same way (`_syncAcctNetNote`: nothing ticked, or a network the terminal has no uplink on; it reads the Network tab's unsaved ticks). Sim `dev/tools/sims/test-terminal-net-gate.mjs` (73). Not live-tested.
- **Hidden characters (tester Aegaeon: "PC owned Actors for Vehicles… hide from Who Knows Who").** CPR has no vehicle actor type, so the GM names them: world setting `hiddenCharacters` (actor ids), edited at Admin → Tools → Hidden Characters (the multi picker with the new `preselected` + `doneLabel` options; with `preselected`, Done may return `[]` and dismissing returns null) or Contacts → Players → Hide. **Hidden means not listed**: sheet, mail and contacts are untouched. `getPlayerCharacters()` leaves them out (`{includeHidden:true}` is for the picker only), which covers every GM tool built on it; `isHiddenCharacter(id)` guards the lists that scan actors themselves (operator pickers + `resolveOperator`, Spam recipients, Character Select, the viewer's character lists, the composer's To search and Send as, terminal Download/Forward targets, the Encoder allowlist, the Overview). **Non-persons (2026-10-30, dev: "Biometric Handoff lets me pick the container"):** `isPersonActor` (no container, demon or Black ICE type, no `isBlackICE` flag) is the one test and `isSelectableCharacter` = person + not hidden. Ownership alone never makes a character: `getOperatorActors` only skipped `blackIce`, so the handoff offered owned containers. **A new actor scan that lists characters uses `isSelectableCharacter`; a link picker uses `isPersonActor`.** Whole-world pickers (Linked actor) still list them, on purpose. Sim `dev/tools/sims/test-hidden-characters.mjs` (44). Not live-tested.

## Tester round 2026-11-02

Sim `dev/tools/sims/test-tester-2026-11-02.mjs` (96). Not live-tested.
- **The ADDRESS decides which identity sent a message: `directoryEntryFor({contactId, actorId, email})` (helpers.js)** — the directory entry for the address, else the contact id, else the character's main identity. `resolveDisplayName` / `resolveDisplayPortrait`, the viewer's `_findSenderContact` / `_senderToAdd` and `buildReply` all use it. Add saves the alias at its own address with no character link (the `pushToPlayer` rule); holding the main does not mark an alias's mail as "in contacts". The directory address replaces `msg.from` only when nothing holds that address (old synthesized mail).
- **A scheduled message's recipients: `scheduledRecipients(d)` / `scheduledRecipientLabel(d)` (SchedulingService.js)**, read by the Agent's Scheduled tab and Admin → Outbox. Several people and groups ride in `recipients`, so `toActorId` + `to` alone read "Unknown". The Agent's Edit reopens the composer with the whole message: recipients, sender identity, attachments, eddies, encryption + ICE, self-destruct, anonymous, send-via and the delivery time (`scheduledComposerState` → `_applyScheduled`, launcher options `recipients` + `scheduled`). **`entry.eddiesHeld` is what the composer really debited; `cancelScheduled` refunds exactly that** (it returns `refunded`) and Schedule charges again, so Edit nets out. An entry with no `eddiesHeld` refunds nothing and Edit warns (a macro's eddies were never paid); migration v5 (`creditOldScheduled`) gave messages already waiting a figure. A terminal send reopens as one (`TerminalService.reopenScheduledSend`, checked before anything is cancelled). **A timed self-destruct restarts at delivery** (`selfDestructAtDelivery`); it used to count from scheduling, so mail could arrive already expired. **A refused scheduled send is finished** (`_deliverScheduled`): it leaves the schedule, refunds (a group's refused share only), is listed under Outbox → Didn't arrive and the GM + scheduling player are told; it used to retry every 10 s silently. `sendMessage` catches its own errors, so any failed result counts as refused and only an exception thrown in `_deliverScheduled` stays pending. **Other clients reload the list on the `scheduledMessages` setting** (`_registerSettingSync`), and a player can't cancel with no GM online: a stale list could otherwise refund mail already delivered.
- **A player's To search** lists other players' characters and their own contacts only (`getRecipientDirectory`).
