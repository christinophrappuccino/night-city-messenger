## Architecture: ACCESS POINTS — every way into a terminal / shard / inbox (2026-10-29, step 1)

Tester ask: "rethink terminal placement… macro options… options for placements?" Dev-approved mocks `dev/mockups/access-points-mock.html` + `access-points-v2-mock.html`; real-markup probe `dev/mockups/access-points-probe.html`; sim `dev/tools/sims/test-access-points.mjs` (39). **Not live-tested.**
- **A ref is `{kind, id}`** — `terminal` / `shard` (item UUID), `inbox` (owner id), `message` (`<ownerId>|<messageId>`). **ONE door: `game.nightcity.openAccess(ref)`** (→ openTerminal / openDataShard / openInbox; a player can't open an inbox they don't own). Every trigger carries a ref: **hotbar macro** (`createAccessMacro(ref, {slot})` — reuses this user's macro for the ref, flag `access`, GM macros land in folder "NCM — Access points"; the body is `accessMacroCommand`, guarded, double-quoted), **drag to the hotbar** (`hotbarDrop` hook: `{type:'NCMAccess', ref}` from an admin rack unit / shard cartridge via `wireAccessDrag`, OR any converted Item dragged from the directory — it becomes a login macro instead of an item-sheet macro), **chat card** (`postAccessCard` → a dialog: who sees it [Everyone / Only GMs / Only <player>; a whisper ALWAYS includes the GMs — `whisper: []` is public] + the colours with a live preview), **journal link** (`@NCM[kind:id]{label}`, `copyAccessLink` → clipboard; `registerAccessEnricher` at init renders a chip; a gone target is a dashed "not found" chip), and the existing map pin. One capture-phase document click listener opens any `[data-ncm-access]`.
- **Handout colours** — world setting `accessHandoutStyle` `{mode: match|default|custom, custom:{primary,accent,bg,text}}` (saved from the Post dialog). Pure `handoutPalette(style, sourceColours)`: match = the terminal's `buildTerminalThemePrefs` / the shard's `buildShardThemePrefs` colours, default = brand, custom = the GM's four (muted text derived). Handouts are body-mounted, so their colours live ONLY in inline `--h-*` properties (`paletteStyle`); fonts fall back hard. CSS `styles/components/access-points.css` (`ncm-ap-card*`, `ncm-ap-chip`, `ncm-ap-dlg*`); every icon-only box has `i { margin:0 }` so glyphs centre.
- **Right-click = "Open · Configure · Terminal options ▸ / Shard options ▸"** (dev-picked layout; first labelled "Night City", renamed the same day as too vague). Foundry v12's directory menu has no submenus, so the ▸ row opens NCM's own `.ncm-ctx-menu` beside it; the inventory row menu does the same (`more: true` entries open a second menu at the row). Both build from ONE `ShardSheetOverride._nightCityEntries(item, actor)` = **ACCESS** (`accessMenuEntries`: Place on this scene [terminal, GM] · Add to hotbar · Post to chat… · Copy journal link [GM]) · **ITEM** (Program Deck, Build a program / Encode more onto it, Rename…, Edit item sheet) · Remove. `_showContextMenu(ev, entries, {title, icon})` gained `{head}` rows, `bad` rows, a title line and on-screen clamping; its colours are tokens now. Admin → Terminals / Shards details have an **Access** button (`tabAct access` → `showAccessMenu(item, button)`, wears the opener's admin preset).
- **The Post dialog is the admin vocabulary** (dev: "dialogs could look nicer like our admin panel"): pure `postDialogHtml` (the thing as a header row in its own colours, banded sections, a segmented Who sees it [Everyone / Only GMs / One player + select], three colour cards each with a swatch strip, the custom pickers, a framed preview). **Every GM dialog got the panel chrome** (admin-theme.css "Admin dialogs, round 2"): canvas header with an act underline, display-face uppercase title, pane-alt body, 30px controls with an act focus ring, a ruled button strip, ONE filled primary (Foundry's `.default` button), a destructive default (data-button delete/remove/purge/wipe/reset/burn) filled red. Dialogs with bespoke chrome are excluded by class (escalate, breach, burn-confirm, link-actor, the picker, time config, role manager). Handout text colours carry `!important` — the admin dialog's `color:inherit` rule otherwise turned the preview card dark on clean-light. Probe `dev/mockups/admin-dialog-probe.html?t=&mode=custom&who=one`.
- **Map pins right-click too** — Open terminal · Configure · Terminal options ▸ (minus "Place on this scene") · THIS PIN: Edit pin… / Remove this pin (GM). **It rides the board's DOM `contextmenu` event, never a wrap of `Note#_onClickRight`**: `TerminalScenePins._onBoardContextMenu` (capture listener on document, `#board` targets only) fires AFTER the button is released, skips a release that travelled >6 px from the right-`pointerdown` (a pan), and hit-tests the terminal pins under the cursor (`_pinAt`: `canvas.canvasCoordinatesFromClient`, radius iconSize/2+6). Two earlier builds wrapped `_onClickRight` and failed live: skipping Foundry's handler left the note's right-drag unfinished, so the map AND the menu followed the mouse; and Foundry binds a note's handlers when it is drawn, so after a reload the wrap never reached existing pins. **Never wrap a placeable's click handlers for a menu — read the DOM event after release.** Sub-menu positions are measured on `pointerdown` (`ShardSheetOverride._subMenuAt`, cursor fallback) — by `click` the menu is detached and measures 0,0. Players get it too (DOM event), double-click still opens.
- **THEMED DIALOGS — `.ncm-themed-dialog` (round 2, same day; dev: "the dialogs look super funky… post to chat is hugged up against the top… Remove chip data should match").** Two real causes, neither visible in the probe: (1) **passing `options.classes` to a Dialog REPLACES Foundry's `['dialog']`** (the admin wrapper only appends its own class), so the Post dialog lost Foundry's dialog layout — the probe frames always carried `dialog`, which hid it. **Every themed dialog opens with `THEMED_DIALOG_CLASSES` = ['dialog', 'ncm-themed-dialog']** (scripts/utils/dialogBody.js); grep for a `classes: [` without `'dialog'` in a Dialog call. (2) The preview was injected in `render` AFTER Foundry had placed the window, so it grew down from too high — the first paint now includes it, and `refit()` re-centres (`setPosition`) whenever the content grows. One look for the small dialogs: `styles/components/ncm-dialog.css` (tokens with an admin→player→hex fallback chain, so a GM gets the admin preset and a player THEIR theme; content padding 0, a header band naming the thing, a full-width button strip, ONE filled default, `.ncm-dlg-bad` = filled red; selectors doubled `.ncm-themed-dialog.ncm-themed-dialog` because admin-theme.css's `.default { color: secondary }` made the filled button's label vanish) + pure `dialogBodyHtml({tone, icon|img, title, sub, kind, lead (**bold**), goes[], stays[], field, hint})` + `themedConfirm` / `themedPrompt` in adminTheme.js (admin or player wrapper by isGM). Used by Post to chat, Rename shard, Remove shard data, Remove terminal data, Remove pin. The generic admin "round 2" rules exclude `.ncm-themed-dialog`. Probe `dev/mockups/admin-dialog-probe.html?t=&as=player`.
- **Step 2 — Admin → WORLD → Access points tab (built same day)** — `tabs/AccessTab.js` (gathers) + pure `tabs/accessModel.js` (rules) + `tab-access.hbs` (`TEMPLATES.ADMIN_TAB_ACCESS`) + `admin-panel/tab-access.css` (`ncm-acc2-*`); context `acc2`, built only while the tab is open; keys 9 = Access, **0 = Tools** now. Gathered: **things** = every terminal + shard (world AND actor-owned; archive copies skipped; `playerHeld` when a player-owned actor carries it), **points** = NCM pins on every scene (position as % of the scene rectangle with padding removed; reach ring from `scenePin.range`), NCM hotbar macros (flag `access`, which users' slots hold them), `@NCM` links in every text journal page, posted chat cards (who they went to + when); any ref a point names that is not a listed thing (an inbox, a message, something deleted) becomes a thing, `found:false` when gone. **Map** = scene-folder shelves (only scenes that have points, plus the viewed scene) with mini-maps on the scene's own thumbnail, an "Off the map" shelf, a desk with the big map + numbered points (Go to it / Open / Edit pin / Remove) and **Place…** (switches to the scene, picks a terminal, `placeAtViewCenter`). **By thing** = groups by kind or holder, chips per way in, "in X's gear", "not reachable anywhere"; the desk lists every way in + **Make access** (`showAccessMenu`). **One toolbar shape for both views** (dev: switching views "looks a bit off and wonky"): the Map | By thing switch + Pop out sit in the page head (`.ncm-tabhd__end`); the toolbar is search · Show · **Group (always present — Map has only "Scene folder")** · Sort · **New**, never wraps at 820, selects have fixed widths. Stats strip = filters with short labels + tooltips: All / On maps / Off the map / Hidden / Broken / **Not reachable** (jumps to By thing). Standing fold rule; hovering a row lights its dot. Live: re-renders on note / macro / user (hotbar) / chat / journal-page hooks. Removing: a pin → the themed Remove pin; a macro / chat card → themed delete; a journal link → opens the page (links live in the page text). Sim `dev/tools/sims/test-access-tab.mjs` (94: rules, the REAL tab over a mocked world, ops ↔ template, styled classes, tokens only, real Handlebars render; `NCM_DUMP` writes acc-map/acc-thing.html). **Not live-tested.** Networks join as a kind later (dev 2026-10-29: a node switches its network off on ITS scene only; one network may have several nodes).
- **Step 3 — placing on a scene (built same day).** **Place on a scene…** (the ACCESS menu entry, now for terminals AND shards, GM; Admin → Access points → Place… presets the scene) opens `openPlaceDialog(item, {sceneId})` (AccessPoints.js; themed, `ncm-plc-*` in ncm-dialog.css; remembers the last choices for the session): Scene (+ Change → the scene picker) · Where (middle of my view / click on the map) · Way in (a pin / a step-on area / both) · Pin reach (squares, 0 = anywhere) or Area size (1–4 squares) · Players see it (right away / hidden until I reveal it), with a live hint. Pure rules in utils/accessPoints.js: `sanitizePlacement`, `placementDialogHtml`, `placementHint`, `areaRect`, `accessRegionScript`. `TerminalScenePins.placeAccess(item, place)` views the scene, gets the point (`_pickPoint`: ONE capture-phase left click on #board → `canvasCoordinatesFromClient`, Esc / right-click cancels, crosshair cursor) and creates:
  - **a pin** (`_createPin`): flags `accessKind` / `accessUuid` / `accessHidden` / optional `accessRange` (+ the old `terminalItemId/Uuid` for terminals, so every older reader still works); `isAccessPin(doc)` is the test everywhere (activation, the right-click hit test, the Access tab). A shard pin opens the shard. The range gate reads the pin's own `accessRange` first, else the terminal's Network-tab setting.
  - **a step-on area** (`_createArea`): a Region (rectangle, `visibility: LAYER`, flag `access`) with ONE `executeScript` behaviour on `tokenEnter`. **Region events are broadcast to every client**, so the script runs everywhere and acts only when `event.user.isSelf`, never for the GM (moving NPCs must not pop terminals), and only for a token that user owns.
  - **Hidden**: a hidden PIN points its `entryId` at a GM-only journal "NCM — Hidden access points" (flag `hiddenAccessPoints`, created once, ownership NONE) — Foundry does not draw a note whose journal a player can't see — and is tinted grey; revealing re-points it at the item's own journal (`journalId` flag). A hidden AREA has its behaviour `disabled`. `setHidden(doc, hidden)` does both; the pin right-click menu has Reveal / Hide, the Access tab an eye per pin / area, a **Hidden** stat, hatched area rectangles on the mini + big maps, dashed hidden points, and Region hooks for live updates. A hidden way in does NOT count as reachable. Unconverting / deleting the item removes its pins AND areas (`removePinsFor`, now also on `-=isDataShard`). Sim `dev/tools/sims/test-access-place.mjs` (33: rules, the script parses + its guards, the REAL placeAccess / setHidden over a mocked scene). Probe `dev/mockups/admin-dialog-probe.html?how=both|pin|area&hid=1`. **Not live-tested** — in Foundry check: the Region behaviour fires for a player's token (and not the GM's), a hidden pin is really invisible to a player, click-on-the-map placement.
- **Step 4 = the macro catch-all, NOT a Monk's Active Tiles integration** (dev's call, same day: "generate macro and you can copy and paste that — anything that has macro access can open it"). The ACCESS menu (GM) gained **Copy macro code** (`copyAccessMacro` → clipboard; an http world without clipboard access gets a dialog with the code selected) and **Make a macro** (`createAccessMacro(ref, {assign:false})` — a world macro in "NCM — Access points", not put on the hotbar, for tools that pick a macro by name). Both carry `accessMacroSnippet(ref, name)`: a header naming what it opens + the warning that it opens for whoever RUNS it, so a trigger module must run it as the triggering player (Monk's Active Tiles, Item Piles, Regions, Stream Deck…), then the guarded `openAccess` call. Made hotbar macros carry the same header.
