## Architecture: terminal FILE REPOSITORY — shared volume, folders, gates, the FILES view (2026-10-25)

Tester (Aegaeon): "how do I add files? do I need a separate terminal? can I combine mail and files to replicate a workstation… let someone browse a file depository." One terminal had always held both — every entry is a typed content entry and a file is one with `envelope: 'file'` — but the ONLY door was the `New message (GM)` button at the bottom of the mailbox sidebar (visible only after logging in), a file's folder was a free-text `filePath` box in the composer, nothing could live on the MACHINE rather than on a login, and nothing was gated. Dev-approved mock: `dev/mockups/terminal-file-repository-mock.html` (three frames; the first flat-list version of frame 2 was rejected because it did not say what goes in what folder — the shipped one is folder-first).

- **The rules are the pure module `scripts/utils/terminalFiles.js`** (no Foundry globals; sim `dev/tools/sims/test-terminal-files.mjs`, 109 checks, drives it + the REAL TerminalService methods over a mocked journal). **A file's folder IS its `file.path`**, stored NORMALISED (`records/2046`, no leading slash — `_buildMessageFlags` and `updateAccountMessage` normalise), so every entry ever authored keeps its place and the tree is built from the paths. **A SHARED VOLUME entry is a page whose `accountId` is `SHARED_SCOPE` (`'__shared__'`)** — on the terminal, not on a login. **`config.files.folders` is the folder REGISTRY** (`{id, scope: '__shared__'|accountId, path, gate:{mode:'everyone'|'admin'|'clearance'|'accounts', min, accountIds}}`, `sanitizeFilesConfig`): it adds what a path string cannot carry — an empty folder, and a GATE. A folder that exists only because files sit in it is DERIVED and ungated; registering it is what the who-can-open select does. **Gates inherit downward and an inner `everyone` never reopens a locked parent** (`effectiveGate`); admin accounts and the GM pass every gate; `clearance` compares the FIRST INTEGER of the account's free-text clearance (`LEVEL 3` → 3, `OMEGA` → never passes a numeric gate). An unknown gate mode sanitises to `everyone`, never to a lock.
- **ONE reader enforces it — `TerminalService.getAccountMessages(item, accountId, {includeShared=true, enforceGates=true})`**: shared pages are included for every account, each message is stamped `accountId` + `shared`, and for a non-GM every file in a folder the account cannot open (or under one) is REMOVED from the list (`visibleEntries`) — so every by-id reader (content actions, exfil, edit, upload) is covered without a second check, and a hidden file is never in the DOM. `getAllMessages` / `getSharedMessages` are the GM-tooling readers. Folder CRUD is GM-only: `saveFileFolder` (upsert by scope+path), `renameFileFolder` / `removeFileFolder` (**both rewrite every file's `file.path` under the old path** via `rewritePlan` — a delete moves files UP a level, nothing vanishes), `moveFile(item, id, {scope, path})` (re-homes an entry across volumes AND re-files it; `updateAccountMessage` accepts `accountId`/`file`/`envelope` for the same reason). `addAccountMessage` accepts `SHARED_SCOPE`. `buildFileTree(item, scope, accountId)` / `canOpenFolder`.
- **Viewer: MAIL | FILES is a VIEW SWITCH (`_view`), not a filter** — the old ALL/MAIL/FILES solo chips (`_envFilter`, `terminalEnvFilter`) are GONE. MAIL = the folder strip as before, holding mail (and a file only in the Trash). FILES = `_filesContext` → the directory tree in the sidebar (`ncm-term__fs-*`: roots HOME + SHARED, dirs with depth, root-level files; a locked dir is `is-locked` with `data-locked="1"` + `data-lock-label`, and **`_onFsOpen` refuses it with the reason**; the GM sees it unlocked with a small open-lock tag) and, in the detail pane, the open folder's **LISTING** (`fs.showListing` branch BEFORE `{{else if selectedMessage}}`: breadcrumb, stats, `..` row, sub-folders, files with type chip / size / modified / owner; a locked sub-folder is a dead row stating why). A file opened from the tree gets a FOLDER back chip (`fsBack`). `_fsSel = {scope, path}` is app state; `_stampMotion`'s signature carries `_view` + `_fsSel`. The GM button reads "Add message or file (GM)" / "Add a file here (GM)" and, in FILES view, opens the composer pre-filed on the open folder and volume. Pagination is off in FILES view (the listing scrolls).
- **Config → Accounts holds the content (`TerminalContentPanel.buildContentContext` → `templates/terminal/partials/config-content.hbs`, `TEMPLATES.TERMINAL_CONFIG_CONTENT`).** A SHARED VOLUME row above the accounts; every account row folds open (`ctToggle`, chevron + mail/file counts) into MAIL (the Identity-tab folders, each with a `+` and collapsible rows) and FILES (the tree as rows: a folder row = chevron · icon · name [click = rename] · **who-can-open `<select>`** · count · + file / + sub-folder / delete; files nest under their folder with a **Move-to `<select>`** over every volume's folders + "＋ New folder…"; a dashed "New folder in /x" input ends every tree). **A tab's context must be SPREAD** — `content` + each account row's `ct` are built in `_prepareContext`; the three selects and the input get manual listeners in `_wireContentTab` (the select-vs-data-action gotcha; every one `stopPropagation`s its click so the account row's `editAccount` does not fire). `ctGateAccounts` / the `accounts` mode uses `showNamePicker({multi:true})` over the accounts. ## Architecture: terminals (Terminal Expansion)

A **Terminal** is a converted Item you "log into" (an account-scoped mailbox), the **sibling of a Data Shard** (a file you crack open). Full design: `dev/design/TERMINAL-EXPANSION.md`. Phase 1 (MVP) is built; the content-type catalog, full method-card auth dialog, composer-grade compose, and tension/liveness features are Phase 2/3.

**Three-flag pattern, mirroring shards.** `flags.<MODULE>.{ isTerminal:true, terminalConfig, terminalState, journalId }` (`DEFAULTS.TERMINAL_CONFIG/STATE/ACCOUNT`). Messages live in **one linked journal** (`type:'terminal'`, `linkedItemId`, folder "Terminals") with each page tagged by `accountId` — `MessageRepository.identifyTerminal(journal)` finds it (flag-based; separate from `identifyInbox`, which returns null for terminals). `TerminalService` (constructed in `registerTerminalSystem.js`, ready/62) parallels `DataShardService` but **delegates** security/ICE/storage. Macro API: `game.nightcity.messenger.convertToTerminal/addTerminalAccount/addTerminalMessage/forceUnlockTerminal/relockTerminal`; launcher `game.nightcity.openTerminal(itemOrId)`.

**Accounts are the heart.** An account = login + mailbox + optional identity link: `{ id, username, displayName, email, masterContactId, actorId, portrait, isAdmin, hidden, security }`. `security` is the **byte-for-byte shared SECURITY_BLOCK** used by networks/shards (password/skill/keyitem/authLogic/lockout/ICE) — author it the same way, never fork the contract. Portrait resolves via `PortraitService.resolvePortrait` (linked master contact → actor → initials). `hidden` accounts aren't on the login card list — reachable only by typing the username via "Log in with another account" (secret login). **The GM always sees hidden accounts** (`getAccounts` includes them for `isGM()`), chipped **HIDDEN** (amber, `hiddenGm` in `_cardContext`) on cards/crt/roster/portraits — "hidden account still shows for me" as GM is by design, not a bug.

**Accounts as inboxes — the delivery mirror (2026-07-12).** A terminal account linked to an identity IS that identity's inbox on the machine: after normal delivery, `MessageService._deliverMessage` (always the GM client) calls `TerminalService.mirrorDeliveryToAccounts(recipientData)` — every account matching the recipient (`masterContactId === toContactId` · `actorId === toActorId` · `email === to` case/space-insensitive; hidden/net-gated accounts still match — those filters are read-time visibility, not ownership) gets a copy via `addAccountMessage` with the **original From + timestamp**, landing unread in the account's Inbox. So a PC replying to a terminal-linked contact shows up on that terminal. Three rules: (1) **the mirror gets its OWN messageId** (`<id>-t-<accountId>`, which doubles as the redelivery guard) — content mutations resolve pages by messageId across ALL journals (`applySiphonToJournal` takes the first hit), so a shared id would desync claim/siphon state between the inbox copy and the mirror; (2) **money never duplicates** (the exfil no-double-grant rule): mirrors carry `eddies: 0` + `_exfilContentData` neutralization — the recipient's real inbox copy is the canonical claim surface; (3) **spam-routed mail is not mirrored** (it would defeat the silent filter), and anonymous mail mirrors the recipient-facing masked clone. Open mailboxes refresh live: the viewer registers create/update/delete `JournalEntryPage` hooks (constructor, `Hooks.off` in `close()`) filtered to the linked journal **and mailbox state only** (a re-render during login/manual would wipe a half-typed password) — this also fixed the standing relayed-write lag. `_playExfilFx` now sets `_animationActive` for its duration so a wipe's own page deletions can't destroy the FX overlay mid-animation (`_debouncedRender` respects the flag). **GM bypass is EXPLICIT, not automatic.** `requiresAuth`/`checkNetworkAccess` bypass only when `terminalState.gmBypassed` is set (via force-unlock), mirroring shard `forceDecrypt` — so a GM sees locked accounts and can test the login (or force-unlock to skip). **Machine uplink (Layer 1) — the TERMINAL's own network, never the player's.** Three layers: Layer 0 = the existing reachability gate (`config.network` — "be on network X to reach this box", player's network, unchanged); **Layer 1** = the machine's own connection (`config.connection = { interfaces: [{networkId, preAuthorized, wired}], defaultNetworkId, allowPlayerSwitching, showSyncHint }` + `state.connection = { currentNetworkId, authenticated }`); **Layer 2** = content gating on that connection. Scene availability/dead zones deliberately don't apply to interfaces (a wired box works in a jam). Key mechanics:
- **Signal display is honest, wired is a flavor flag.** The mailbox-HUD bars light per the ACTIVE uplink's signal (`_uplinkContext` top-level `signal`/`sigLabel`; the network's configured `signalStrength`, app-wide thresholds 80/50/25) — they were four always-lit `<b>`s before ("CitiNet 75% but bars show 100"). Per-interface **`wired`** (config Network tab checkbox next to pre-authorized) = a physical LAN drop: signal reads 100, dropdown rows show `· wired`, the pill gets a small glyph, and **the HUD swaps the signal bars for a hardline icon entirely** (`.ncm-term__hud-wired`, `{{#if uplink.wired}}` branch). The wired glyph is **`fa-network-wired`, NOT `fa-ethernet`** ("looks like a comb" — dev). **Display/fiction only** — gating already ignores scene jamming for uplinks, so `wired` changes no mechanics.
- **`state.connection.currentNetworkId` uses the sentinel `'__DEFAULT__'`** (= follow `config.connection.defaultNetworkId`), NOT an absent key — whole-state rewrites (`_updateSession`, force-unlock) would otherwise convert "never set" into an explicit `null` and silently kill the boot default. `null` = explicitly disconnected (LOCAL ONLY). `TerminalService.getUplink` resolves sentinel → default → validates the network still exists AND is still an interface (else degrades to LOCAL ONLY). Logic sim: scratchpad `test-uplink.mjs` (12 cases).
- **Gating check is `networkVisibility`-shaped** (shard shape: `{restricted, allowedNetworks[], allowedTypes[]}`) via two service methods: `uplinkReaches(item, nv)` (raw, no GM bypass — used to badge **OFF-NET** chips for the GM) and `isContentVisible(item, nv)` (GM-bypassing enforcement). **Accounts** carry `account.network` — gated accounts **VANISH** for players (filtered in `getAccounts`, which also kills the secret-login path since `_resolveAuthAccount` goes through it); the GM keeps them with an OFF-NET chip. **Messages** carry per-message `networkVisibility` (persisted in `_buildMessageFlags` + read in `MessageRepository._pageToMessage` — the field-by-field gotcha, needed for composer edit-prefill); the mailbox filters them and shows a GM-toggleable **"N objects failed to sync"** hint (`showSyncHint`, counted within the current folder). **Exfil copies never carry `networkVisibility`** (a downloaded file is local — `createMessage` doesn't persist the key, `exfilToShard` doesn't pass it).
- **Network icons honor custom images**: the uplink dropdown rows and the network-gate cards render via `{{{ncm-net-icon theme}}}` (`_uplinkContext`/`_gateContext` expose the full `theme` block) — a network configured with `iconMode:'image'` + `customImage` in Network Manager shows its logo, like every other network list in the app. Wired interfaces keep the hardline-glyph override; `.ncm-net-icon-img` gets a fit rule (radius+padding) scoped to the terminal icon squares.
- **Switching**: the UPLINK pill (login hero — pre-login switching matters since gated accounts vanish — + mailbox HUD) opens a dropdown of interfaces (partial `templates/terminal/partials/uplink.hbs`, invoked `{{> … uplink align="right"}}` in the hero). GM writes via `TerminalService.setUplink`; **players relay** via `SOCKET_OPS.TERMINAL_NET_REQUEST` (no RESULT op — the flag write syncs and the viewer re-renders off an `updateItem` hook registered in the constructor, removed in `close()`, skipped during boot/granted animations). A non-`preAuthorized` secured interface opens a **join-challenge console** (`ncm-term__netauth` overlay; the NETWORK's own security block; lockout keyed `${itemId}::net::${networkId}`; skill bypass defaults Interface/DV15 so core nets always give players a roll path; GM gets a "join without credentials" row); success stamps `state.connection.authenticated[networkId]` — the machine remembers.
- **Mid-session uplink switch away from a gated account drops the session** — `_prepareContext` detects the now-unreachable account and bounces to login ("UPLINK LOST").
- The composer's Network-Visibility fieldset is **no longer hidden for terminal targets** (the `{{#unless isTerminalTarget}}` wrap is gone; terminal targets get uplink-specific hint copy).

**Auth runs through the shared method-card dialog.** Selecting a secured account (`TerminalViewerApp._onSelectAccount`, card/roster/portrait styles) opens `NetworkAuthDialog.showForAccount(item, accountId)` — the SAME dialog networks use, with password + skill (`SkillService.performCheck`) + key-item + **strict AND/OR** (`authLogic`) + lockout (`SecurityService`, keyed `terminalId::accountId`) + Black ICE (`failureMode==='damage'`). The dialog was **parameterized via a source-adapter seam** (`scripts/ui/NetworkManagement/SecurityAuthAdapters.js`): `NetworkAuthDialog._adapter` abstracts the four source-specific ops — `refresh()` (fresh source-shaped `{id,name,type,theme,description,security}`), `checkPassword()`, `checkSkill()`, `grant()` — so `_prepareContext`/handlers stay source-agnostic and `this.networkId` is just the SecurityService key (a network id, or `terminalId::accountId`). `NetworkAuthAdapter` preserves network behavior byte-identically (delegates to `networkService.authenticate*`/`grantAuth`, which own their sounds + `_authenticatedNetworks` grant + events); `TerminalAuthAdapter` reads the account's SECURITY_BLOCK directly (password/DV compare, plays the sounds itself, `grant()` is a no-op — the dialog's resolve drives `_loginSuccess`). On the terminal side GM bypass is per-login (the dialog's GM-bypass button resolves success; the account's `gmBypassed` force-unlock still short-circuits `requiresAuth` before the dialog opens). **The lockscreen/keypad inline-password paths and the secret-login ("another account") console stay as quick-entry shortcuts** — single-method, no strict AND/OR (typed-username secret login has no known account until submit). **Player session-state writes RELAY (2026-07-13):** login/account-switch/logout write `terminalState.sessions` on the world item, which players can't update ("User Player lacks permission to update Item" was the first real player-login bug) — `TerminalService._updateSession` emits `SOCKET_OPS.TERMINAL_SESSION_REQUEST` when `!isGM()` and the GM handler lands the write via `applySessionUpdate` (the uplink-relay pattern; no RESULT op — the flag write syncs back and the viewer re-renders off its updateItem hook; the viewer proceeds locally on its own `_accountId`, so the lag is invisible). The auth CHECK itself is client-side reads (the shard-relay trust model) — only the persistence relays.

**A login lasts as long as the WINDOW (2026-10-27, tester: "logged in once with the password, then got straight in forever — after closing, refreshing, even after the GM changed the password; only Force-Unlock + Relock reset it").** The viewer used to trust `terminalState.sessions[actor].loggedInAccounts`, a world flag nothing but Relock cleared. Closing the window, **Log out** (now ends the whole session), switching operator, a forced lockout and a refresh (the constructor clears a leftover record via `_clearStoredSession`) all end it; a GM change to the account's password or login methods kicks an open session back to login (`CREDENTIALS CHANGED`, via the updateItem hook). **Login footprints + "N new since last login" (2026-08-14).** The machine records who logged into which account: `_updateSession`'s GM-side branch (the ONE chokepoint every session establishment lands in — same reason onLogin residents fire there) appends to **`terminalState.loginLog`** (`_appendLoginLog`: `{ts (game clock), accountId, username, operatorId, operatorName}`, capped `LOGIN_LOG_CAP` 50). **Exfil + the Recovered folder.** `allowExfil` (master switch) gates "To my Agent" (copy to the player's inbox) and "Burn to Shard" (`DataShardService.addMessage` onto a target item).
